# 정렬 알고리즘의 성능 및 안정성 비교

## 0. 개요

이 과제는 `sort_compare.c`를 직접 실행한 결과(`Seed state : 8042631481360990334`, 데이터 10,000개)를 근거로 작성했다. 표의 숫자는 모두 실행 출력에서 가져왔고, 차이와 비율은 그 숫자로 계산했다.
구현 코드에서 시드는 time, clock, 주소로 정해지므로 실행할 때마다 결과가 달라지며, README의 숫자는 Seed state : 8042631481360990334로 실행한 결과이다. 현재 과제의 결과와 동일하게 시드를 고정하려면 rs에 시드값을 대입하면 된다.

- 소스코드: [sort_compare.c](https://github.com/stroplezero/Data-Structures-2-/blob/main/Project10/sort_compare.c)
- 실제 실행 결과: [8. 실제 실행 결과](#8-실제-실행-결과)

## 1. 방법
- 데이터는 `{key1, key2, idx}` 구조체. key1과 key2는 0~1,000,000 범위의 독립된 난수이며, `idx`는 원래 입력 순서이고, 정렬 기준이 아니라 안정성 검증에만 사용한다.
- **비교 횟수**: 두 데이터의 key1을 비교할 때마다 1회이며, 반복문의 조건 검사는 세지 않음.
- **이동 횟수**: 데이터 구조체 전체를 대입하거나 복사할 때마다 1회로 세아림.
  - 교환은 임시 변수를 거쳐 총 3회.
  - 삽입 정렬은 임시 변수 저장 1회, 한 칸 이동마다 1회, 최종 위치 대입 1회임.
- 모든 알고리즘은 `memcpy`로 복사한 같은 입력을 받는다. (원본 복사와 입력 데이터 생성은 횟수에 포함하지 않음.)
- 정렬이 끝나면 매번 오름차순인지 확인했고, 모든 경우에 `Sorted OK`가 나왔다.
- 일반 버블과 조기 종료 버블은 같은 함수에서 조기 종료 여부만 다르게 했다.

## 2. 무작위 데이터 100회 실험
매 반복마다 새로운 난수 데이터 10,000개를 만들고, 네 정렬에 같은 복사본을 주었다. 100회 모두 정렬이 올바르다고 나왔다(`All 100 trials sorted correctly: YES`).

| 알고리즘 | 총 비교 횟수 | 평균 비교 횟수 | 평균 이동 횟수 |
|---|---:|---:|---:|
| 선택 정렬 | 4,999,500,000 | 49,995,000.00 | 29,970.72 |
| 버블 정렬 | 4,999,500,000 | 49,995,000.00 | 74,992,193.40 |
| 버블 정렬(조기 종료) | 4,998,503,893 | 49,985,038.93 | 74,992,193.40 |
| 삽입 정렬 | 2,500,738,769 | 25,007,387.69 | 25,017,395.80 |

- 선택 정렬과 일반 버블 정렬의 비교 횟수는 정확히 N(N−1)/2 = 49,995,000회였다. 입력과 관계없이 모든 쌍을 검사하기 때문이다.
- 삽입 정렬의 비교는 약 2,500만 회로, 선택·버블의 약 절반이었다. 삽입 정렬은 삽입 위치를 찾으면 비교를 멈추므로, 데이터가 맨 뒤에 들어가면 비교 1번, 맨 앞에 들어가면 비교 i번이기 때문에 무작위 데이터에서는 정렬된 앞부분을 평균 절반만 훑는다.
- 이동 횟수는 선택(약 3만) < 삽입(약 2,500만) < 버블(약 7,499만) 순이었다.
  - 선택 정렬은 교환을 최대 N−1번만 하므로 이동이 가장 적다.
  - 버블 정렬의 평균 이동 74,992,193.4를 3으로 나누면 24,997,397.8이다. 이는 교환 횟수, 곧 역전 쌍(앞의 값이 뒤의 값보다 큰 쌍) 수의 평균이었다.
  - 삽입 정렬의 평균 이동 25,017,395.8에서 임시 저장과 최종 대입 2(N−1) = 19,998을 빼면 24,997,397.8이다. 버블 정렬에서 구한 값과 같으며, 두 알고리즘의 이동은 모두 역전 쌍 수로 설명할 수 있다.

## 3. 일반 버블 정렬과 조기 종료 버블 정렬

| 입력 | 일반 버블 비교 | 조기 종료 비교 | 감소량 | 감소율 |
|---|---:|---:|---:|---:|
| 무작위(100회 평균) | 49,995,000 | 49,985,038.93 | 약 9,961 | 약 0.02% |
| 정렬됨 | 49,995,000 | 9,999 | 49,985,001 | 약 99.98% |
| 역순 | 49,995,000 | 49,995,000 | 0 | 0% |
| 일부 정렬 | 49,995,000 | 48,739,680 | 1,255,320 | 약 2.5% |

- 두 방식의 이동 횟수는 네 경우 모두 같다(무작위 74,992,193.40, 역순 149,984,874, 일부 정렬 2,031,558, 정렬됨 0). 조기 종료는 교환이 없는 순회를 건너뛸 뿐, 교환 횟수는 바꾸지 않는다.
- **정렬된 데이터**: 첫 순회(9,999회 비교)에서 교환이 한 번도 없어 바로 종료되며, 비교가 약 5천만 회에서 9,999회로 줄었다.
- **역순 데이터**: 모든 순회에서 교환이 일어나 조기 종료가 한 번도 작동하지 않아 일반 버블과 결과가 완전히 같다.
- **무작위 데이터**: 감소가 약 0.02%로, 일반 버블과 조기 종료 버블의 차이가 거의 없다. 교환이 없는 순회는 마지막 몇 번뿐이기 때문이다.
- **일부 정렬 데이터**: 약 2.5%만 줄었다. 입력이 대부분 정렬되어 있어도 어긋난 원소 하나가 정리되는 데 여러 순회가 필요해, 교환이 없는 순회가 일찍 나오지 않기 때문이다.

## 4. 입력 상태별 성능 비교

### 4.1 입력 데이터 생성 방법
- `base`: 100회와 별도로 생성한 데이터.
- **무작위**: 2장의 100회 실험 결과를 사용했다.
- **정렬됨**: 무작위 원본 `base`를 key1 오름차순으로 정렬했다.
- **역순**: 같은 `base`를 key1 내림차순으로 정렬했다.
- **일부 정렬**: 정렬된 데이터에서 임의의 두 위치를 골라 서로 바꾸는 작업을 N/100 = **100번** 반복했다. 이렇게 생성된 데이터는 전체 10,000개 중 최대 약 200개(2%)의 위치만 어긋난 거의 정렬된 상태이다.
- 정렬됨, 역순, 일부 정렬은 모두 같은 `base`에서 만들었고, 사전 정렬과 교환 작업은 비교·이동 횟수에 포함하지 않았다.

#### AI 활용

부분 정렬 데이터의 생성 방법은 AI(대화형 AI 어시스턴트)의 도움을 받아 설계했다.   
부분 정렬을 만들 수 있는 방법에 대해 AI는 아래의 5가지 방법과 특징을 알려주었다.

| 방법 | 만드는 법 | 정렬 정도 조절 |
|---|---|---|
| 1. 무작위 쌍 교환 | 정렬된 데이터에서 임의의 두 위치를 k번 교환 | 교환 횟수 k |
| 2. 일부 구간만 섞기 | 정렬된 데이터의 한 구간(예: 앞 10%)만 무작위로 섞음 | 섞는 구간의 비율 |
| 3. 일부 구간만 정렬 | 무작위 데이터에서 앞 p%만 정렬하고 나머지는 그대로 둠 | 정렬한 구간의 비율 p |
| 4. 소수 원소의 무작위 교란 | 정렬된 데이터에서 일부 원소 k개를 뽑아 새 무작위 값으로 바꾸거나 임의 위치로 옮김 | 바꾼 원소 수 k |
| 5. 근접 교환 (지역적 흐트러짐) | 각 원소를 가까운 위치(±w 범위)와만 교환 | 범위 w |

**각 방법의 특징**
- **1. 무작위 쌍 교환**: 구현이 간단하고, 교환된 원소가 멀리 떨어져 있어서, 개수는 적은데 역전 쌍은 많이 생긴다.
- **2. 구간 섞기**: 흐트러진 곳이 한 덩어리로 모인다. 나머지는 완전히 정렬되어 있어서, 삽입 정렬은 그 구간에서만 비용이 든다.
- **3. 구간 정렬**: 앞부분은 정렬, 뒷부분은 무작위이며, 정렬된 앞부분이 있어서 삽입 정렬의 이득이 일부만 생긴다. 정렬 비율 p로 정도를 단계별로 만들기 쉽다.
- **4. 소수 교란**: 대부분의 원소는 제자리에 있고, 몇 개만 크게 벗어난다. 현실의 "거의 정렬된 로그 데이터"에 가깝다.
- **5. 근접 교환**: 모든 원소가 제자리 근처에 있어서 역전 쌍이 상대적으로 적고, 버블 정렬이 조기 종료로 이득을 보기 쉽다.

위의 5가지 방법 중에서 어떤 것이 과제에 적합할지 물어보자 AI는 "무작위 쌍 교환"을 선택했다. AI가 이 방법을 선택한 이유는 다음과 같았다.

- 정렬된 상태에서 시작해 교환 횟수만으로 어긋남의 정도를 조절할 수 있다.
- 교환 횟수와 위치가 코드에 그대로 드러나서, "어떤 기준으로 어느 정도 정렬된 데이터를 만들었는지" 명확하게 설명할 수 있다.
- 같은 원본(`base`)에서 정렬 데이터, 역순 데이터, 부분 정렬 데이터를 모두 만들 수 있어 입력 간 비교가 공정하다.

AI의 도움으로 정리한 구체적인 설계는 다음과 같다.

1. 무작위 원본 데이터를 key1 오름차순으로 정렬해 정렬된 데이터를 만든다.
2. 이를 복사한 뒤, `rnd()`로 임의의 두 위치 i, j를 골라 두 데이터를 서로 바꾸는 작업을 N/100 = 100번 반복한다.
3. 최대 약 200개(전체의 약 2%)의 데이터만 제자리를 벗어난 "거의 정렬된" 상태가 된다.

교환 횟수 100번(N/100)은 AI가 대부분은 정렬되어 있고 일부만 흐트러진 상태가 되도록 임의로 정한 값이다. AI가 이 값으로 임의로 정한 이유는 다음과 같이 설명하였기에 이 횟수를 채택하였다.
- 전체 데이터의 1%에 해당하는 교환 횟수라서, 설명하기 쉽다.
- 교환 하나가 위치 2개를 건드리므로 최대 약 200개(2%)만 제자리를 벗어나기 때문에 "부분 정렬"이라고 부를 만하다.
- 교환 횟수가 너무 적으면 정렬된 데이터와 차이가 거의 없고, 너무 많으면 무작위 데이터와 비슷해지기 때문에 둘 사이의 중간쯤으로 잡았다.

### 4.2 정렬된 데이터
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 0 |
| 버블 정렬 | 49,995,000 | 0 |
| 버블 정렬(조기 종료) | 9,999 | 0 |
| 삽입 정렬 | 9,999 | 19,998 |

- 선택 정렬과 일반 버블은 정렬된 입력에서도 비교를 모두 한다. 이동은 교환할 일이 없기 때문에 0이다.
- 조기 종료 버블과 삽입 정렬은 N−1 = 9,999회만 비교한다.
- 삽입 정렬의 이동 19,998은 2(N−1)과 같다. 이는 모든 원소가 임시 저장 1회와 최종 대입 1회만 했고, 데이터를 한 칸씩 미는 이동은 없었다는 뜻이다.

### 4.3 역순 데이터
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 15,051 |
| 버블 정렬 | 49,995,000 | 149,984,874 |
| 버블 정렬(조기 종료) | 49,995,000 | 149,984,874 |
| 삽입 정렬 | 49,995,000 | 50,014,956 |

- 네 알고리즘의 비교가 모두 49,995,000으로 같다. 삽입 정렬과 조기 종료 버블에게는 최악의 입력이 된다.
- 버블 정렬의 이동 149,984,874를 3으로 나누면 49,994,958이고, 삽입 정렬의 이동에서 19,998을 뺀 값도 49,994,958로 같다. 이 값은 최대 역전 쌍 수인 N(N−1)/2 = 49,995,000에 가깝다. 42의 차이는 key1이 같은 쌍은 역전 쌍이 아니기에 역순이어도 역전 쌍에서 제외되기 때문에 나타나는 것으로 추정된다.
- 선택 정렬의 이동 15,051은 교환 5,017번(×3)이다. 약 N/2번의 교환으로 끝나, 이동이 가장 적다. 버블 정렬의 이동은 선택의 약 1만 배이다.

### 4.4 일부 정렬된 데이터
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 303 |
| 버블 정렬 | 49,995,000 | 2,031,558 |
| 버블 정렬(조기 종료) | 48,739,680 | 2,031,558 |
| 삽입 정렬 | 687,185 | 697,184 |

- 삽입 정렬의 비교 687,185는 무작위(약 2,500만)의 약 2.7%, 역순(49,995,000)의 약 1.4%이다. 이동도 697,184로 크게 줄었다.
- 삽입 정렬의 이동에서 19,998을 뺀 677,186과 비교에서 9,999를 뺀 677,186이 같다. 버블 정렬의 이동 2,031,558을 3으로 나눈 값도 677,186이다. 이 입력의 역전 쌍은 677,186개이고, 세 알고리즘의 이동 횟수가 모두 이 수로 설명된다.
- 선택 정렬은 어긋난 위치만 제자리로 보내면 되기 때문에 비교가 그대로이고 이동만 303(교환 101번)이다.
- 일반 버블은 비교가 줄지 않았고, 조기 종료로 약 2.5%를 아끼기만 했다.

### 4.5 입력 상태가 성능에 미치는 영향

비교 횟수:

| 알고리즘 | 정렬됨 | 일부 정렬 | 무작위(평균) | 역순 |
|---|---:|---:|---:|---:|
| 선택 정렬 | 49,995,000 | 49,995,000 | 49,995,000 | 49,995,000 |
| 버블 정렬 | 49,995,000 | 49,995,000 | 49,995,000 | 49,995,000 |
| 버블(조기 종료) | 9,999 | 48,739,680 | 49,985,038.93 | 49,995,000 |
| 삽입 정렬 | 9,999 | 687,185 | 25,007,387.69 | 49,995,000 |

이동 횟수:

| 알고리즘 | 정렬됨 | 일부 정렬 | 무작위(평균) | 역순 |
|---|---:|---:|---:|---:|
| 선택 정렬 | 0 | 303 | 29,970.72 | 15,051 |
| 버블 정렬 | 0 | 2,031,558 | 74,992,193.40 | 149,984,874 |
| 삽입 정렬 | 19,998 | 697,184 | 25,017,395.80 | 50,014,956 |

- **선택 정렬**: 입력 상태가 비교에 영향을 주지 않고, 이동은 어느 상태에서도 3만 회 이하이다.
- **일반 버블 정렬**: 비교는 고정이다. 이동은 역전 쌍 수에 비례해, 정렬됨 0에서 역순 약 1.5억 회까지 변한다.
- **조기 종료 버블**: 정렬된 입력에서만 큰 이득이 있다. 일부 정렬에서는 2.5%, 무작위에서는 0.02%만 줄고, 역순에서는 이득이 없었다.
- **삽입 정렬**: 비교와 이동이 모두 역전 쌍 수를 따라 변한다. 입력 상태에 가장 민감하며, 거의 정렬된 입력에서 가장 유리하다.

## 5. 안정성 검증

### 5.1 검증 방법
각 데이터에 원래 입력 순서 `idx`를 저장했다. 정렬 후 인접한 두 데이터의 key1이 같은데 앞 데이터의 `idx`가 뒤 데이터의 `idx`보다 큰 쌍을 세어 `order violations`로 출력했다. 0이면 안정, 1개 이상이면 불안정이다. 정렬 결과가 올바른지(`sorted`)도 함께 확인했다.

### 5.2 사용한 입력 데이터
데이터 10,000개이고, key1을 0~99 범위로 제한해 첫 번째 키의 중복이 많게 만들었다(`Key1 in 0..99`). key2는 기존 과제와 동일하게 0~1,000,000 난수이며, 네 정렬에 같은 복사본을 주었다.   
무작위 데이터(0~1,000,000)에서는 key1 중복이 적어 안정성이 잘 드러나지 않을 수 있어 첫 번째 키가 중복되는 별도의 시험 데이터를 만들어 검증하였다.

### 5.3 결과
```
[Large test] 10000 items, Key1 in 0..99 (many duplicates)
  Selection Sort        : sorted=yes, order violations=3303
  Bubble Sort           : sorted=yes, order violations=0
  Insertion Sort (>)    : sorted=yes, order violations=0
  Insertion Sort (>=)   : sorted=yes, order violations=9900
```

| 알고리즘 | 정렬 결과 | 순서 위반 수 | 판정 |
|---|---|---:|---|
| 선택 정렬 | 올바름 | 3,303 | 불안정 |
| 버블 정렬 | 올바름 | 0 | 안정 |
| 삽입 정렬 (`>`) | 올바름 | 0 | 안정 |
| 삽입 정렬 (`>=`) | 올바름 | 9,900 | 불안정 |

- 삽입 정렬 `>=`의 위반 9,900은 인접 쌍 9,999개에서 key1이 달라지는 경계 99개를 뺀 값과 같다. key1이 100종류라고 가정하면, key1이 같은 인접 쌍이 모두 뒤집혔다는 뜻이다.

### 5.4 원인
- **선택 정렬(불안정)**: 최소값을 현재 위치로 가져오려고 멀리 떨어진 두 데이터를 교환한다. 현재 위치에 있던 데이터가 뒤쪽으로 건너뛰면서, 같은 key1을 가진 다른 데이터를 앞지를 수 있기 때문에 위반 3,303이 생겼다.
- **버블 정렬(안정)**: 인접한 두 데이터만 교환하고, 조건이 `a[j].key1 > a[j+1].key1`로 엄격한 부등호다. key1이 같으면 교환하지 않으므로 같은 key1끼리 서로를 넘을 수 없기 때문에 위반이 0이었다.
- **삽입 정렬**: 안정성이 이동 조건의 연산자에 따라 갈린다.

### 5.5 삽입 정렬에서 `>`와 `>=`의 차이
```c
move = useGE ? (a[j].key1 >= cur.key1) : (a[j].key1 > cur.key1);
```
- **Case A (`>`)**: 삽입할 값과 key1이 같은 데이터를 만나면 이동을 멈추고, 그 바로 뒤에 삽입한다. 같은 key1 중 나중에 들어온 데이터가 뒤에 놓이므로 순서가 유지되기 때문에 위반 0이며, 안정하다.
- **Case B (`>=`)**: 같은 key1 데이터도 뒤로 밀어내고 그 앞에 삽입한다. 나중에 들어온 데이터가 앞에 놓여 같은 key1 그룹의 순서가 뒤집히기 때문에 위반 9,900이며, 불안정하다.
- 두 경우 모두 key1 기준 오름차순 정렬은 올바르게 되었지만(`sorted=yes`). 다른 점은 key1이 같은 데이터들의 상대 순서뿐이었다.

## 6. 성능 차이의 원인

| 알고리즘 | 비교 횟수를 정하는 것 | 이동 횟수를 정하는 것 | 안정성 |
|---|---|---|---|
| 선택 정렬 | 입력과 무관하게 항상 N(N−1)/2 | 교환이 최대 N−1번이라 매우 적음 | 불안정 |
| 버블 정렬 | 항상 N(N−1)/2 (조기 종료는 교환 없는 순회에서 종료) | 역전 쌍 하나당 3회 | 안정 |
| 삽입 정렬 | 역전 쌍 수 + 약 N | 역전 쌍 수 + 2(N−1) | `>` 안정, `>=` 불안정 |

- 선택 정렬은 입력 상태와 상관없이 같은 횟수를 비교하지만, 이동이 가장 적다.
- 버블 정렬은 역전 쌍마다 3회씩 이동해서, 무작위·역순에서 이동이 가장 많다.
- 삽입 정렬은 비교와 이동이 역전 쌍 수에 비례해서, 정렬에 가까울수록 빠르다.
- 조기 종료는 정렬된 입력에서만 크게 효과가 있다.

## 7. 결론
1. 무작위 데이터에서 비교 횟수는 삽입(약 2,500만) < 선택 = 버블(약 5,000만)이다. 이동 횟수는 선택(약 3만) < 삽입(약 2,500만) < 버블(약 7,499만)이다.
2. 정렬된 데이터와 거의 정렬된 데이터에서는 삽입 정렬이 가장 유리하다. 정렬된 입력에서는 조기 종료 버블도 같은 비교 횟수(9,999)였다.
3. 역순 데이터는 모든 알고리즘에 최악이다. 특히 버블 정렬의 이동이 약 1.5억 회로 가장 많았다.
4. 버블 정렬과 삽입 정렬(`>`)은 key1끼리 서로를 넘지 않기에 안정하고, 선택 정렬과 삽입 정렬(`>=`)은 key1끼리 서로를 넘을 수 있기에 불안정하다.
5. 조기 종료 여부와 `>` 대 `>=`라는 조건이 성능과 안정성에 실질적인 차이를 만들 수 있음을 알 수 있다.
