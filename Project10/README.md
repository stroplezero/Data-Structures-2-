# 정렬 알고리즘의 성능 및 안정성 비교 (실행 결과 기반)

이 문서는 `sort_compare.c`를 직접 실행한 결과(`Seed state : 8042631481360990334`, 데이터 10,000개)만을 근거로 작성했습니다. 표의 숫자는 모두 실행 출력에서 가져왔고, 차이와 비율은 그 숫자로 계산했습니다.

## 1. 실험 방법
- 데이터는 `{key1, key2, idx}` 구조체입니다. key1과 key2는 0~1,000,000 범위의 독립된 난수입니다. `idx`는 원래 입력 순서이고, 정렬 기준이 아니라 안정성 검증에만 씁니다.
- 정렬은 key1 오름차순으로만 합니다. 선택, 버블, 조기 종료 버블, 삽입 정렬을 직접 구현했고 라이브러리 정렬 함수는 쓰지 않았습니다.
- **비교 횟수**: 두 데이터의 key1을 비교할 때마다 1회입니다. 반복문의 조건 검사는 세지 않습니다.
- **이동 횟수**: 데이터 구조체 전체를 대입하거나 복사할 때마다 1회입니다.
  - 교환은 임시 변수를 거쳐 3회입니다.
  - 삽입 정렬은 임시 변수 저장 1회, 한 칸 이동마다 1회, 최종 위치 대입 1회입니다.
- 모든 알고리즘은 `memcpy`로 복사한 같은 입력을 받습니다. 원본 복사와 입력 데이터 생성은 횟수에 포함하지 않습니다.
- 정렬이 끝나면 매번 오름차순인지 확인했고, 모든 경우에 `Sorted OK`가 나왔습니다.
- 일반 버블과 조기 종료 버블은 같은 함수에서 조기 종료 여부만 다르게 했습니다.

## 2. 무작위 데이터 100회 실험
매 반복마다 새로운 난수 데이터 10,000개를 만들고, 네 정렬에 같은 복사본을 주었습니다. 100회 모두 정렬이 올바랐습니다(`All 100 trials sorted correctly: YES`).

| 알고리즘 | 총 비교 횟수 | 평균 비교 횟수 | 평균 이동 횟수 |
|---|---:|---:|---:|
| 선택 정렬 | 4,999,500,000 | 49,995,000.00 | 29,970.72 |
| 버블 정렬 | 4,999,500,000 | 49,995,000.00 | 74,992,193.40 |
| 버블 정렬(조기 종료) | 4,998,503,893 | 49,985,038.93 | 74,992,193.40 |
| 삽입 정렬 | 2,500,738,769 | 25,007,387.69 | 25,017,395.80 |

- 선택 정렬과 일반 버블 정렬의 비교 횟수는 정확히 N(N−1)/2 = 49,995,000회입니다. 입력과 관계없이 모든 쌍을 검사하기 때문입니다.
- 삽입 정렬의 비교는 약 2,500만 회로, 선택·버블의 약 절반입니다. 삽입 위치를 찾으면 비교를 멈추므로, 무작위 데이터에서는 정렬된 앞부분을 평균 절반만 훑습니다.
- 이동 횟수는 선택(약 3만) < 삽입(약 2,500만) < 버블(약 7,499만) 순입니다.
  - 선택 정렬은 교환을 최대 N−1번만 하므로 이동이 가장 적습니다.
  - 버블 정렬의 평균 이동 74,992,193.4를 3으로 나누면 24,997,397.8입니다. 이는 교환 횟수, 곧 역전 쌍(앞의 값이 뒤의 값보다 큰 쌍) 수의 평균입니다.
  - 삽입 정렬의 평균 이동 25,017,395.8에서 임시 저장과 최종 대입 2(N−1) = 19,998을 빼면 24,997,397.8입니다. 버블 정렬에서 구한 값과 같습니다. 두 알고리즘의 이동은 모두 역전 쌍 수로 설명됩니다.

## 3. 일반 버블 정렬과 조기 종료 버블 정렬

| 입력 | 일반 버블 비교 | 조기 종료 비교 | 감소량 | 감소율 |
|---|---:|---:|---:|---:|
| 무작위(100회 평균) | 49,995,000 | 49,985,038.93 | 약 9,961 | 약 0.02% |
| 정렬됨 | 49,995,000 | 9,999 | 49,985,001 | 약 99.98% |
| 역순 | 49,995,000 | 49,995,000 | 0 | 0% |
| 일부 정렬 | 49,995,000 | 48,739,680 | 1,255,320 | 약 2.5% |

- 두 방식의 이동 횟수는 네 경우 모두 같습니다(무작위 74,992,193.40, 역순 149,984,874, 일부 정렬 2,031,558, 정렬됨 0). 조기 종료는 교환이 없는 순회를 건너뛸 뿐, 교환 횟수는 바꾸지 않습니다.
- **정렬된 데이터**: 첫 순회(9,999회 비교)에서 교환이 한 번도 없어 바로 종료합니다. 비교가 약 5천만 회에서 9,999회로 줄었습니다.
- **역순 데이터**: 모든 순회에서 교환이 일어나 조기 종료가 한 번도 작동하지 않습니다. 일반 버블과 결과가 완전히 같습니다.
- **무작위 데이터**: 감소가 약 0.02%로, 거의 효과가 없습니다. 교환이 없는 순회는 마지막 몇 번뿐이기 때문입니다.
- **일부 정렬 데이터**: 약 2.5%만 줄었습니다. 입력이 대부분 정렬되어 있어도 어긋난 원소 하나가 정리되는 데 여러 순회가 필요해, 교환이 없는 순회가 일찍 나오지 않습니다.

## 4. 입력 상태별 성능 비교

### 4.1 입력 데이터 생성 방법
- **무작위**: 2장의 100회 실험 결과를 사용했습니다.
- **정렬됨**: 무작위 원본 `base`를 key1 오름차순으로 정렬했습니다.
- **역순**: 같은 `base`를 key1 내림차순으로 정렬했습니다.
- **일부 정렬**: 정렬된 데이터에서 임의의 두 위치를 골라 서로 바꾸는 작업을 N/100 = **100번** 반복했습니다. 전체 10,000개 중 최대 약 200개(2%)의 위치만 어긋난 거의 정렬된 상태입니다.
- 정렬됨, 역순, 일부 정렬은 모두 같은 `base`에서 만들었습니다. 사전 정렬과 교환 작업은 비교·이동 횟수에 포함하지 않았습니다.
- **AI 활용**: (여기에 AI에게 한 질문과 답변 요약, 그리고 그중 어떤 방법을 왜 골랐는지 직접 적으세요.)

### 4.2 정렬된 데이터
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 0 |
| 버블 정렬 | 49,995,000 | 0 |
| 버블 정렬(조기 종료) | 9,999 | 0 |
| 삽입 정렬 | 9,999 | 19,998 |

- 선택 정렬과 일반 버블은 정렬된 입력에서도 비교를 모두 합니다. 이동은 0입니다. 교환할 일이 없기 때문입니다.
- 조기 종료 버블과 삽입 정렬은 N−1 = 9,999회만 비교합니다.
- 삽입 정렬의 이동 19,998은 2(N−1)과 같습니다. 모든 원소가 임시 저장 1회와 최종 대입 1회만 했고, 데이터를 한 칸씩 미는 이동은 없었다는 뜻입니다.

### 4.3 역순 데이터
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 15,051 |
| 버블 정렬 | 49,995,000 | 149,984,874 |
| 버블 정렬(조기 종료) | 49,995,000 | 149,984,874 |
| 삽입 정렬 | 49,995,000 | 50,014,956 |

- 네 알고리즘의 비교가 모두 49,995,000으로 같습니다. 삽입 정렬과 조기 종료 버블에게는 최악의 입력입니다.
- 버블 정렬의 이동 149,984,874를 3으로 나누면 49,994,958입니다. 삽입 정렬의 이동에서 19,998을 뺀 값도 49,994,958로 같습니다. 이 값은 최대 역전 쌍 수 N(N−1)/2 = 49,995,000에 가깝습니다. 42 차이는 key1이 같은 쌍은 역전 쌍이 아니기 때문으로 추정됩니다.
- 선택 정렬의 이동 15,051은 교환 5,017번(×3)입니다. 약 N/2번의 교환으로 끝나, 이동이 가장 적습니다. 버블 정렬의 이동은 선택의 약 1만 배입니다.

### 4.4 일부 정렬된 데이터
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 303 |
| 버블 정렬 | 49,995,000 | 2,031,558 |
| 버블 정렬(조기 종료) | 48,739,680 | 2,031,558 |
| 삽입 정렬 | 687,185 | 697,184 |

- 삽입 정렬의 비교 687,185는 무작위(약 2,500만)의 약 2.7%, 역순(49,995,000)의 약 1.4%입니다. 이동도 697,184로 크게 줄었습니다.
- 삽입 정렬의 이동에서 19,998을 뺀 677,186과 비교에서 9,999를 뺀 677,186이 같습니다. 버블 정렬의 이동 2,031,558을 3으로 나눈 값도 677,186입니다. 이 입력의 역전 쌍은 677,186개이고, 세 알고리즘의 이동 횟수가 모두 이 수로 설명됩니다.
- 선택 정렬은 비교가 그대로이고 이동만 303(교환 101번)입니다. 어긋난 위치만 제자리로 보내면 되기 때문입니다.
- 일반 버블은 비교가 줄지 않습니다. 조기 종료로 약 2.5%를 아끼는 데 그칩니다.

비교 횟수:

이동 횟수:

- **삽입 정렬**: 비교와 이동이 모두 역전 쌍 수를 따라 변합니다. 입력 상태에 가장 민감하며, 거의 정렬된 입력에서 가장 유리합니다.

## 5. 안정성 검증

### 5.1 검증 방법
각 데이터에 원래 입력 순서 `idx`를 저장했습니다. 정렬 후 인접한 두 데이터의 key1이 같은데 앞 데이터의 `idx`가 뒤 데이터의 `idx`보다 큰 쌍을 세어 `order violations`로 출력했습니다. 0이면 안정, 1개 이상이면 불안정입니다. 정렬 결과가 올바른지(`sorted`)도 함께 확인했습니다.

### 5.2 사용한 입력 데이터
데이터 10,000개이고, key1을 0~99 범위로 제한해 중복이 많게 만들었습니다(`Key1 in 0..99`). key2는 0~1,000,000 난수입니다. 네 정렬에 같은 복사본을 주었습니다. 무작위 데이터(0~1,000,000)에서는 key1 중복이 적어 안정성이 잘 드러나지 않을 수 있어 따로 만들었습니다.

### 5.3 결과
```
[Large test] 10000 items, Key1 in 0..99 (many duplicates)
  Selection Sort        : sorted=yes, order violations=3303
  Bubble Sort           : sorted=yes, order violations=0
  Insertion Sort (>)    : sorted=yes, order violations=0
  Insertion Sort (>=)   : sorted=yes, order violations=9900
```

| 알고리즘 | 정렬 결과 | 순서 위반 수 | 판정 |
|---|---|---:|---|
| 선택 정렬 | 올바름 | 3,303 | 불안정 |
| 버블 정렬 | 올바름 | 0 | 안정 |
| 삽입 정렬 (`>`) | 올바름 | 0 | 안정 |
| 삽입 정렬 (`>=`) | 올바름 | 9,900 | 불안정 |

- 삽입 정렬 `>=`의 위반 9,900은 인접 쌍 9,999개에서 key1이 달라지는 경계 99개를 뺀 값과 같습니다. key1이 100종류라고 가정하면, key1이 같은 인접 쌍이 모두 뒤집혔다는 뜻입니다.

### 5.4 원인
- **선택 정렬(불안정)**: 최소값을 현재 위치로 가져오려고 멀리 떨어진 두 데이터를 교환합니다. 현재 위치에 있던 데이터가 뒤쪽으로 건너뛰면서, 같은 key1을 가진 다른 데이터를 앞지를 수 있습니다. 그래서 위반 3,303이 생겼습니다.
- **버블 정렬(안정)**: 인접한 두 데이터만 교환하고, 조건이 `a[j].key1 > a[j+1].key1`로 엄격한 부등호입니다. key1이 같으면 교환하지 않으므로 같은 key1끼리 서로를 넘을 수 없습니다. 위반이 0이었습니다.
- **삽입 정렬**: 안정성이 이동 조건의 연산자에 따라 갈립니다.

### 5.5 삽입 정렬에서 `>`와 `>=`의 차이
```c
move = useGE ? (a[j].key1 >= cur.key1) : (a[j].key1 > cur.key1);
```
- **Case A (`>`)**: 삽입할 값과 key1이 같은 데이터를 만나면 이동을 멈추고, 그 바로 뒤에 삽입합니다. 같은 key1 중 나중에 들어온 데이터가 뒤에 놓이므로 순서가 유지됩니다. 위반 0, 안정입니다.
- **Case B (`>=`)**: 같은 key1 데이터도 뒤로 밀어내고 그 앞에 삽입합니다. 나중에 들어온 데이터가 앞에 놓여 같은 key1 그룹의 순서가 뒤집힙니다. 위반 9,900, 불안정입니다.
- 두 경우 모두 key1 기준 오름차순 정렬은 올바르게 됐습니다(`sorted=yes`). 다른 점은 key1이 같은 데이터들의 상대 순서뿐입니다.
- 이 실험은 안정성만 비교했고, `>=`와 `>`의 비교·이동 횟수는 측정하지 않았습니다. 이 차이에 대해서는 판단하지 않았습니다.

## 6. 성능 차이의 원인

| 알고리즘 | 비교 횟수를 정하는 것 | 이동 횟수를 정하는 것 | 안정성 |
|---|---|---|---|
| 선택 정렬 | 입력과 무관하게 항상 N(N−1)/2 | 교환이 최대 N−1번이라 매우 적음 | 불안정 |
| 버블 정렬 | 항상 N(N−1)/2 (조기 종료는 교환 없는 순회에서 종료) | 역전 쌍 하나당 3회 | 안정 |
| 삽입 정렬 | 역전 쌍 수 + 약 N | 역전 쌍 수 + 2(N−1) | `>` 안정, `>=` 불안정 |

- 선택 정렬은 입력 상태와 상관없이 같은 횟수를 비교하지만, 이동이 가장 적습니다.
- 버블 정렬은 역전 쌍마다 3회씩 이동해서, 무작위·역순에서 이동이 가장 많습니다.
- 삽입 정렬은 비교와 이동이 역전 쌍 수에 비례해서, 정렬에 가까울수록 빠릅니다.
- 조기 종료는 정렬된 입력에서만 크게 효과가 있습니다.

## 7. 결론
1. 무작위 데이터에서 비교 횟수는 삽입(약 2,500만) < 선택 = 버블(약 5,000만)입니다. 이동 횟수는 선택(약 3만) < 삽입(약 2,500만) < 버블(약 7,499만)입니다.
2. 정렬된 데이터와 거의 정렬된 데이터에서는 삽입 정렬이 가장 유리합니다. 정렬된 입력에서는 조기 종료 버블도 같은 비교 횟수(9,999)입니다.
3. 역순 데이터는 모든 알고리즘에 최악입니다. 특히 버블 정렬의 이동이 약 1.5억 회로 가장 많습니다.
4. 안정 정렬은 버블 정렬과 삽입 정렬(`>`)이고, 선택 정렬과 삽입 정렬(`>=`)은 불안정합니다.
5. 조기 종료 여부와 `>` 대 `>=`라는 작은 조건 하나가 성능과 안정성에 실질적인 차이를 만들었습니다.
