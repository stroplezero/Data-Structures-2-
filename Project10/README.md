# 정렬 알고리즘의 성능 및 안정성 비교

선택 정렬, 버블 정렬(일반 / 조기 종료), 삽입 정렬(`>` / `>=`)을 C로 직접 구현했습니다. 정렬 키는 Key 1(첫 번째 키)만 사용하며, 데이터 10,000개에 대해 숫자 비교 횟수와 데이터 이동 횟수를 측정하고 안정성을 검증했습니다.

- 소스: `sort_compare.c`
- 빌드: `gcc -O2 -o sort_compare.exe sort_compare.c` 또는 `cl /O2 sort_compare.c`
- 난수 시드는 실행마다 달라집니다. 아래 수치는 `Seed state : 8042631481360990334`로 실행한 결과입니다. 다시 실행하면 수치가 조금 달라지지만 경향은 같습니다.

---

## 1. 실험 방법

### 1.1 데이터와 측정 기준
- 데이터 한 개는 `{key1, key2, idx}` 구조체입니다. key1, key2는 0~1,000,000 범위의 독립된 난수이고, `idx`는 원래 입력 순서입니다. `idx`는 정렬 기준이 아니라 안정성 검증용입니다.
- 난수는 xorshift64로 직접 만들었습니다. Windows의 `rand()`는 최댓값이 32767이라 100만까지 만들 수 없기 때문입니다.
- **비교 횟수**: 두 데이터의 key1을 비교할 때마다 1회입니다. 반복문의 인덱스 조건은 세지 않습니다.
- **이동 횟수**: 데이터 구조체 전체를 대입하거나 복사할 때마다 1회입니다.
  - 교환은 `temp`를 거치므로 3회입니다.
  - 삽입 정렬은 임시 변수 저장 1회, 한 칸 이동마다 1회, 최종 위치 대입 1회입니다.
- 원본 배열 복사와 시험 데이터 생성은 횟수에 포함하지 않습니다.
- 모든 알고리즘은 `memcpy`로 복사한 동일한 입력을 받습니다. 정렬 후에는 `isSorted()`로 오름차순인지 확인합니다.

### 1.2 구현 요약
| 알고리즘 | 구현 |
|---|---|
| 선택 정렬 | 미정렬 구간에서 key1이 최소인 위치를 찾아 현재 위치와 교환합니다. 같은 위치면 교환하지 않습니다. |
| 버블 정렬 | 인접한 두 데이터를 비교해 앞이 크면 교환합니다. 매 순회마다 뒤쪽 한 칸씩 구간을 줄입니다. |
| 버블 정렬(조기 종료) | 위와 동일하되, 한 순회에서 교환이 한 번도 없으면 종료합니다. |
| 삽입 정렬 | 현재 값을 임시 변수에 저장하고, 이동 조건이 참인 동안 앞 데이터를 한 칸씩 뒤로 밉니다. 이동 조건은 Case A(`>`)와 Case B(`>=`) 두 가지입니다. |

일반 버블과 조기 종료 버블은 같은 함수에 플래그 하나만 다르게 두었으므로, 조기 종료 여부만 다릅니다.

## 2. 무작위 데이터 100회 실험 결과

매 반복마다 새 난수 데이터 10,000개를 만들고, 네 가지 정렬(선택, 버블, 조기 종료 버블, 삽입)에 같은 복사본을 주었습니다. 100회 모두 정렬 결과가 올바랐습니다(`All 100 trials sorted correctly: YES`).

| 알고리즘 | 총 비교 횟수 | 평균 비교 횟수 | 평균 이동 횟수 |
|---|---:|---:|---:|
| 선택 정렬 | 4,999,500,000 | 49,995,000.00 | 29,970.72 |
| 버블 정렬 | 4,999,500,000 | 49,995,000.00 | 74,992,193.40 |
| 버블 정렬(조기 종료) | 4,998,503,893 | 49,985,038.93 | 74,992,193.40 |
| 삽입 정렬 | 2,500,738,769 | 25,007,387.69 | 25,017,395.80 |

### 분석
- **선택 정렬과 일반 버블 정렬**은 비교 횟수가 정확히 N(N−1)/2 = 49,995,000회입니다. 입력과 상관없이 모든 쌍을 확인하는 구조이기 때문입니다.
- **삽입 정렬**의 비교 횟수는 약 N²/4 = 25,000,000회입니다. 무작위 데이터에서는 이미 정렬된 앞부분 중 평균 절반만 훑으면 삽입 위치를 찾기 때문입니다. 선택, 버블의 약 절반입니다.
- **이동 횟수**는 알고리즘마다 크게 다릅니다.
  - 선택 정렬은 교환을 최대 N−1번(3회씩)만 하므로 평균 약 3만 회입니다. 셋 중 가장 적습니다.
  - 버블 정렬은 역전 쌍(inversion) 하나를 교환할 때마다 3회씩 이동합니다. 무작위 데이터의 역전 쌍 수는 평균 N(N−1)/4 ≈ 24,997,500개이므로 이동은 약 3배인 7,499만 회입니다. 측정값 74,992,193과 거의 같습니다.
  - 삽입 정렬은 역전 쌍 하나당 1회씩 밀기 때문에 이동이 약 2,500만 회입니다. 여기에 원소마다 임시 저장과 최종 대입 2회가 더해집니다(2(N−1)=19,998). 측정값 25,017,395.80은 이 계산과 맞습니다.
  - 따라서 이동 횟수는 버블 > 삽입 > 선택 순입니다.

## 3. 일반 버블 정렬과 조기 종료 버블 정렬

| 입력 | 일반 버블 비교 | 조기 종료 비교 | 차이 |
|---|---:|---:|---:|
| 무작위(평균) | 49,995,000 | 49,985,038.93 | 약 9,961 감소 (0.02%) |
| 정렬됨 | 49,995,000 | 9,999 | 49,985,001 감소 (99.98%) |
| 역순 | 49,995,000 | 49,995,000 | 0 |
| 일부 정렬 | 49,995,000 | 48,739,680 | 1,255,320 감소 (약 2.5%) |

이동 횟수는 네 경우 모두 두 방식이 같습니다. 조기 종료는 교환이 없는 순회를 건너뛸 뿐 교환 횟수를 바꾸지 않기 때문입니다.

- **무작위 데이터**: 효과가 거의 없습니다. 무작위 데이터에서는 거의 끝까지 교환이 일어나고, 교환이 없는 순회가 생기는 것은 맨 마지막 몇 번뿐이기 때문입니다.
- **정렬된 데이터**: 첫 순회(9,999회 비교)에서 교환이 하나도 없으므로 바로 종료합니다. 비교 횟수가 O(N²)에서 O(N)으로 줄어듭니다.
- **역순 데이터**: 모든 순회에서 교환이 일어나 조기 종료가 발동하지 않습니다. 일반 버블과 완전히 같습니다.
- **일부 정렬 데이터**: 오른쪽으로 보내야 할 큰 값이 순회마다 한 칸씩 정리되므로, 흐트러진 정도에 따라 몇 순회 일찍 끝납니다. 이번 실험에서는 약 2.5% 감소했습니다. 큰 값이 앞쪽에 있고 작은 값이 뒤쪽에 있으면, 작은 값이 한 순회에 한 칸씩만 앞으로 가기 때문에 많은 순회가 필요합니다. 그래서 감소 폭이 크지 않았습니다.

## 4. 입력 상태별 성능 비교

### 4.1 입력 데이터 생성 방법
- **무작위**: 2장의 100회 평균 결과를 사용했습니다.
- **정렬됨**: 무작위 원본 `base`를 key1 오름차순으로 정렬해 만들었습니다.
- **역순**: 같은 `base`를 key1 내림차순으로 정렬해 만들었습니다.
- **일부 정렬**: 정렬된 데이터에서 임의의 두 위치를 골라 서로 바꾸는 작업을 N/100 = **100번** 반복했습니다. 전체 10,000개 중 최대 약 200개(2%)의 위치만 어긋난 거의 정렬된 상태입니다.
  - 이 방식은 AI(챗봇)에게 부분 정렬 데이터 생성 방법을 물어보고 제안받은 세 가지 후보(① 일부 원소의 위치를 임의로 교환, ② 일정 구간만 정렬하거나 섞기, ③ 정렬된 데이터에 소수의 무작위 교란)에서 ①을 골라 쓴 것입니다.
  - 어느 정도 정렬되었는지는 교환 횟수 하나로 조절할 수 있고, 결과를 재현하고 분석하기 쉬워서 이 방식을 선택했습니다.
  - 교환 쌍 수를 바꾸면 정렬 정도를 바꿀 수 있습니다.
  - (AI에게 실제로 한 질문과 답변은 제출 전에 본인 기록으로 바꿔 쓰세요.)
- 정렬, 교환 등 입력 준비 과정의 연산은 비교 횟수와 이동 횟수에 포함하지 않았습니다.

### 4.2 정렬된 데이터 (Sorted)
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 0 |
| 버블 정렬 | 49,995,000 | 0 |
| 버블 정렬(조기 종료) | 9,999 | 0 |
| 삽입 정렬 | 9,999 | 19,998 |

- 선택 정렬과 일반 버블은 데이터가 정렬되어 있어도 비교를 전부 합니다. 비교 구조가 입력과 무관하기 때문입니다. 다만 교환할 데이터가 없어 이동은 0입니다(선택 정렬은 최소 위치가 현재 위치와 같으면 교환을 건너뜁니다).
- 조기 종료 버블과 삽입 정렬은 N−1 = 9,999회 비교만 합니다(O(N)).
- 삽입 정렬에서 이동 19,998회는 모두 "임시 변수 저장 + 최종 위치 대입"입니다. 즉 N−1번 각각 2회입니다. 데이터를 한 칸씩 미는 이동은 한 번도 없습니다.

### 4.3 역순 데이터 (Reverse-Sorted)
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 15,051 |
| 버블 정렬 | 49,995,000 | 149,984,874 |
| 버블 정렬(조기 종료) | 49,995,000 | 149,984,874 |
| 삽입 정렬 | 49,995,000 | 50,014,956 |

- 모든 알고리즘의 비교가 N(N−1)/2로 같습니다. 삽입 정렬과 조기 종료 버블에게는 최악의 경우입니다.
- 역전 쌍이 최대(약 N(N−1)/2)입니다.
  - 버블 정렬은 역전 쌍 하나당 3회 이동하므로 약 1억 5천만 회입니다. 이론값 3×49,995,000 = 149,985,000과 거의 같습니다. 측정값이 약간 작은 것은 key1이 같은 쌍은 교환하지 않기 때문입니다.
  - 삽입 정렬은 약 5,000만 회입니다. 이는 역전 쌍 수에 2(N−1)을 더한 값입니다.
  - 선택 정렬은 약 N/2 = 5,000번 교환(×3 = 15,000)이면 충분하므로 15,051회입니다. 역순에서 선택 정렬은 이동이 가장 적고, 버블 정렬은 선택의 약 1만 배입니다.

### 4.4 일부 정렬된 데이터 (Partially Sorted)
| 알고리즘 | 비교 | 이동 |
|---|---:|---:|
| 선택 정렬 | 49,995,000 | 303 |
| 버블 정렬 | 49,995,000 | 2,031,558 |
| 버블 정렬(조기 종료) | 48,739,680 | 2,031,558 |
| 삽입 정렬 | 687,185 | 697,184 |

- 삽입 정렬의 비교(687,185)는 무작위(약 2,500만)의 약 2.7%, 역순(약 5,000만)의 약 1.4%입니다. 이동도 약 70만 회로 크게 줄었습니다. 역전 쌍 수에 비례해 비용이 줄기 때문입니다.
- 이 입력의 역전 쌍은 약 677,186개로 추정됩니다. 삽입 정렬의 이동에서 19,998을 뺀 값, 그리고 비교에서 9,999를 뺀 값이 모두 이 수와 일치하고, 버블 이동(2,031,558)은 이 수의 정확히 3배입니다. 즉 세 알고리즘의 이동 횟수가 모두 역전 쌍 수로 설명됩니다.
- 선택 정렬은 비교는 그대로이고 이동만 303회(101번 교환)입니다. 어긋난 원소만 제자리를 찾아가면 되기 때문입니다.
- 버블 정렬은 비교 횟수가 줄지 않아, 이동은 줄어도 비교 비용은 그대로입니다. 조기 종료로 약 2.5%를 아끼는 데 그칩니다.

### 4.5 입력 상태가 성능에 미치는 영향 종합

비교 횟수 기준:

| 알고리즘 | 정렬됨 | 일부 정렬 | 무작위 | 역순 |
|---|---:|---:|---:|---:|
| 선택 정렬 | 49,995,000 | 49,995,000 | 49,995,000 | 49,995,000 |
| 버블 정렬 | 49,995,000 | 49,995,000 | 49,995,000 | 49,995,000 |
| 버블 정렬(조기 종료) | 9,999 | 48,739,680 | 약 49,985,039 | 49,995,000 |
| 삽입 정렬 | 9,999 | 687,185 | 약 25,007,388 | 49,995,000 |

이동 횟수 기준:

| 알고리즘 | 정렬됨 | 일부 정렬 | 무작위 | 역순 |
|---|---:|---:|---:|---:|
| 선택 정렬 | 0 | 303 | 약 29,971 | 15,051 |
| 버블 정렬 | 0 | 2,031,558 | 약 74,992,193 | 149,984,874 |
| 삽입 정렬 | 19,998 | 697,184 | 약 25,017,396 | 50,014,956 |

- **선택 정렬**: 입력 상태가 비교 횟수에 영향을 주지 않습니다. 이동만 0~약 3만 회로 늘 적습니다. 이동 비용이 큰 환경(큰 데이터)에서는 선택 정렬이 유리합니다.
- **버블 정렬(일반)**: 비교는 고정입니다. 이동은 역전 쌍 수에 정비례해서, 정렬된 상태에서 역순까지 0에서 약 1.5억 회로 변합니다.
- **조기 종료 버블**: 거의 완전히 정렬된 입력에서만 이득을 봅니다. 한 군데라도 큰 값이 앞쪽에 어긋나 있으면 이득이 급격히 사라집니다(일부 정렬 2.5%).
- **삽입 정렬**: 비교와 이동이 모두 역전 쌍 수에 비례합니다. 정렬됨(O(N)) → 일부 정렬(비용 작음) → 무작위(N²/4) → 역순(N²/2) 순으로 늘어납니다. 입력 상태에 가장 민감한 대신, 거의 정렬된 데이터에서는 세 알고리즘 중 가장 빠릅니다.

## 5. 안정성 검증

### 5.1 검증 방법
- 안정 정렬은 key1이 같은 데이터들의 상대적인 순서가 정렬 전후에 유지되는 정렬입니다.
- 각 데이터에 원래 입력 순서 `idx`를 저장하고, 정렬이 끝난 뒤 인접한 두 데이터의 key1이 같은데 `idx`가 뒤집힌(앞 데이터의 idx > 뒤 데이터의 idx) 쌍의 개수(`order violations`)를 셉니다. 위반이 0이면 안정, 1개 이상이면 불안정입니다.
- 정렬 결과가 올바른지(`sorted=yes`)도 함께 확인했습니다.

### 5.2 검증에 사용한 입력 데이터
1. **대규모 중복 데이터(프로그램 실행)**: 데이터 10,000개, key1을 0~99 범위의 난수로 제한해 중복이 매우 많게 만들었습니다(key1당 평균 약 100개). key2는 0~1,000,000 난수이고, 네 가지 정렬이 같은 복사본을 사용했습니다. 무작위 데이터(0~1,000,000)에서는 중복이 적어 안정성이 드러나지 않을 수 있으므로 따로 만들었습니다.
2. **소규모 예시 데이터(과제 예시, 손으로 추적)**: `(idx0: 527,100) (idx1: 527,200) (idx2: 125,300) (idx3: 892,400)`.
   - 선택 정렬: i=0에서 최소값 125(idx2)를 idx0 위치와 교환하면 `(125,300) (527,200) (527,100) (892,400)`이 됩니다. 이후 교환이 없어 **(527,200)이 (527,100)보다 앞**에 놓입니다. → 순서 역전, 불안정.
   - 삽입 정렬 `>=`: idx1의 (527,200)을 삽입할 때 앞의 (527,100)이 `>=` 조건을 만족해 뒤로 밀리므로 (527,200)이 (527,100) 앞에 놓입니다. → 불안정.
   - 버블 정렬과 삽입 정렬 `>`는 두 (527,*)가 서로 바뀌지 않아 순서가 유지됩니다. → 안정.

### 5.3 검증 결과 (프로그램 실행 결과)

```

  Bubble Sort           : sorted=yes, order violations=0

  Insertion Sort (>=)   : sorted=yes, order violations=9900
```

|---|---|---:|---|

| 삽입 정렬 (`>`) | 올바름 | 0 | **안정** |
| 삽입 정렬 (`>=`) | 올바름 | 9,900 | **불안정** |

- 위반 9,900이라는 값은 인접 쌍 9,999개 중 key1이 같은 쌍(key1 값이 100종류이므로 서로 다른 값 경계 99개를 제외한 9,900개)이 **전부** 뒤집혔다는 뜻입니다. `>=`는 같은 값끼리 순서를 완전히 반대로 만듭니다.

### 5.4 원인 분석
- **선택 정렬이 불안정한 이유**: 최소값을 현재 위치로 가져오기 위해 멀리 떨어진 두 데이터를 **교환**합니다. 이때 현재 위치에 있던 데이터가 멀리 뒤쪽으로 건너뛰어, 그 사이 또는 뒤에 있던 같은 key1 데이터를 앞질러 버립니다. 5.2의 예시에서 (527,100)이 125와 교환되어 뒤쪽으로 갔고, (527,200)이 앞에 남았습니다.
- **버블 정렬이 안정한 이유**: **인접한** 두 데이터만 교환하고, 교환 조건이 `a[j] > a[j+1]`로 엄격한 부등호입니다. key1이 같으면 교환하지 않으므로 같은 key1끼리는 서로를 넘어갈 수 없습니다.
- **삽입 정렬의 안정성은 비교 연산자에 따라 달라집니다.** 아래에서 설명합니다.

### 5.5 삽입 정렬에서 `>`와 `>=`의 차이
```c
move = useGE ? (a[j].key1 >= cur.key1) : (a[j].key1 > cur.key1);
```
- **Case A (`>`)**: 삽입할 값(`cur`)과 key1이 같은 데이터를 만나면 이동을 멈추고, 그 **바로 뒤**에 `cur`를 삽입합니다. 같은 key1에서 나중에 들어온 데이터가 항상 뒤에 놓이므로 입력 순서가 유지됩니다. 위반 0, **안정**.
- **Case B (`>=`)**: 같은 key1 데이터를 만나도 계속 뒤로 밀어내므로 `cur`가 같은 key1 데이터들의 **앞**으로 들어갑니다. 나중에 들어온 데이터가 먼저 놓이므로 같은 key1 그룹 안의 순서가 뒤집힙니다. 위반 9,900, **불안정**.
- **비교 횟수와 이동 횟수에도 차이가 생깁니다.** `>=`는 key1이 같은 데이터까지 추가로 이동시키므로 중복이 많을수록 이동이 늘어납니다. 반대로 `>`는 같은 값 앞에서 멈추므로 이동이 적고, 이미 정렬된 데이터에서도 이동이 불필요하게 늘지 않습니다. 정렬 결과(key1 기준 오름차순)는 두 경우 모두 올바르지만, key1이 같은 데이터의 순서만 다릅니다.
- 정리하면 안정성은 알고리즘의 큰 구조가 아니라 "같은 값일 때 이동할 것인가"라는 **작은 조건 하나**로 결정됩니다.

## 6. 성능 차이의 원인 정리

| 알고리즘 | 비교 횟수의 결정 요인 | 이동 횟수의 결정 요인 | 안정성 |
|---|---|---|---|
| 선택 정렬 | 입력과 무관하게 항상 N(N−1)/2 | 교환은 최대 N−1번뿐이라 매우 적음 | 불안정 (먼 거리 교환) |
| 버블 정렬 | 항상 N(N−1)/2 (조기 종료 시 교환 없는 순회에서 종료) | 역전 쌍 하나당 3회 (가장 많음) | 안정 |
| 삽입 정렬 | 역전 쌍 수 + 약 N | 역전 쌍 수 + 2(N−1) | `>` 안정 / `>=` 불안정 |

- 세 알고리즘의 시간 복잡도는 평균과 최악에서 모두 O(N²)입니다. 하지만 비교와 이동이 **무엇에 비례하는가**가 다릅니다.
  - 선택 정렬은 입력과 상관없는 고정 비교 횟수 때문에 정렬 상태의 영향을 가장 덜 받습니다.
  - 버블 정렬은 역전 쌍마다 3회씩 이동하므로 이동 비용이 크고, 조기 종료가 없으면 정렬된 입력에서도 비교를 모두 합니다.
  - 삽입 정렬은 비교와 이동이 역전 쌍 수에 비례하므로, 정렬에 가까울수록 빨라집니다.
- 조기 종료는 "교환이 없다 = 정렬 완료"라는 사실을 활용해 정렬된 입력에서 O(N)이 되게 하지만, 무작위·역순 입력에서는 효과가 없고 일부 정렬에서도 효과가 제한적입니다(2.5%).

## 7. 결론
1. 무작위 데이터: 비교 횟수는 삽입(약 2,500만) < 선택 = 버블(약 5,000만)입니다. 이동 횟수는 선택(약 3만) < 삽입(약 2,500만) < 버블(약 7,500만)입니다.
2. 정렬된 데이터와 거의 정렬된 데이터에서는 삽입 정렬(과 정렬된 입력에서의 조기 종료 버블)이 압도적으로 유리하고, 선택 정렬은 입력 상태와 상관없이 비교 횟수가 같습니다.
3. 역순 데이터는 모든 알고리즘에 최악이며, 특히 버블 정렬의 이동이 약 1억 5천만 회로 가장 많습니다.
4. 안정성은 버블 정렬, 삽입 정렬(`>`)이 안정이고 선택 정렬, 삽입 정렬(`>=`)이 불안정입니다.
5. 단순한 조건 하나(조기 종료 플래그, `>` 대 `>=`)가 성능과 안정성에 실질적인 차이를 만들었습니다.
