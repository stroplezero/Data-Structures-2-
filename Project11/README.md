# 삽입 정렬과 쉘 정렬의 성능 비교

무작위 정수 데이터에 대해 삽입 정렬(Insertion Sort)과 쉘 정렬(Shell Sort)을 수행하고, **데이터 값 사이의 비교 횟수**를 측정해 성능을 분석했다. 쉘 정렬은 간격(Gap) 수열을 두 가지(기본 간격, Knuth 수열)로 나누어 비교했다.

## 1. 방법

- 데이터 크기 n: 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- 각 크기마다 원본 무작위 데이터를 한 번 생성하고, 세 알고리즘이 **같은 원본의 복사본**을 정렬했다. 정렬은 오름차순이다.
- 데이터 값끼리 비교할 때마다 결과와 관계없이 1회로 셌다. 반복문 인덱스 검사, 데이터 생성, 배열 복사는 제외했다.
- 정렬 후 오름차순 여부를 검사했고, 정렬 오류가 있다면 [경고] 문구가 출력되도록 하였다. 실제 실행 결과에서 해당 문구가 출력되지 않았으므로 모든 경우 정상 정렬되었다.
- 쉘 정렬
  - 기본: n/2, n/4, …, 1
  - Knuth: h(k+1) = 3h(k) + 1 (1, 4, 13, 40, …). n보다 작은 가장 큰 값부터 역순으로 적용

## 3. 분석

### 3.1 데이터 크기 증가에 따른 비교 횟수 변화

n을 2배로 늘렸을 때 비교 횟수가 몇 배가 되는지 정리하면 다음과 같다.

| n 변화 | 삽입 정렬 | 쉘 (기본) | 쉘 (Knuth) |
|---|---:|---:|---:|
| 1,000 → 2,000 | 3.89배 | 2.25배 | 2.35배 |
| 2,000 → 4,000 | 3.91배 | 2.40배 | 2.33배 |
| 4,000 → 8,000 | 4.16배 | 2.42배 | 2.59배 |
| 8,000 → 16,000 | 3.94배 | 2.33배 | 2.18배 |

- **삽입 정렬**은 n이 2배가 될 때 비교 횟수가 약 4배가 된다. 비교 횟수가 약 n²/4에 비례하는 **O(n²)** 증가를 보인다.
- **쉘 정렬**은 n이 2배가 될 때 비교 횟수가 약 2.2\~2.6배가 된다. n²(4배)보다 훨씬 완만하고, n log n(약 2.1배)보다는 약간 가파르다. 두 쉘 정렬 모두 n²보다 낮은 차수로 증가한다.  
  
- 따라서 n이 커질수록 두 방식의 격차가 커진다.

### 3.2 삽입 정렬과 쉘 정렬의 성능 차이

삽입 정렬 비교 횟수를 쉘 정렬 비교 횟수로 나눈 비율이다.

| n | 삽입 / 쉘(기본) | 삽입 / 쉘(Knuth) |
|---:|---:|---:|
| 1,000 | 16.2배 | 18.9배 |
| 2,000 | 28.0배 | 31.3배 |
| 4,000 | 45.7배 | 52.6배 |
| 8,000 | 78.4배 | 84.5배 |
| 16,000 | 132.4배 | 152.5배 |
| 20,000 | 165.4배 | 184.9배 |

n=20,000에서 삽입 정렬은 약 1억 회를 비교했지만 쉘 정렬은 약 55~60만 회에 그쳤다. 차이는 n이 커질수록 벌어지는데, 그 이유는 삽입 정렬은 n²/4로 늘고 쉘 정렬은 그보다 훨씬 느리게 늘기 때문이다.

**원인**
- 삽입 정렬은 원소를 **한 칸씩** 이동시킨다. 무작위 배열에서 한 원소가 평균적으로 앞쪽 원소의 절반과 비교되므로 총 비교 횟수가 약 n²/4가 된다. 멀리 떨어진 제자리로 가려면 그 거리만큼 비교와 이동이 필요하다.
- 쉘 정렬은 초반에 큰 간격으로 정렬하므로 원소가 **한 번에 멀리** 이동한다. 이렇게 먼 거리의 역전(순서가 뒤집힌 쌍)이 먼저 많이 해소된다.  
  이후 간격을 줄여 가면서 배열은 점점 정렬된 상태에 가까워진다. 삽입 정렬은 거의 정렬된 배열에서 비교 횟수가 n에 가까워지므로, 마지막 h=1 단계는 비용이 작다.  
  쉘 정렬은 큰 이동을 앞 단계에 몰아서 처리하고, 마지막에는 거의 정렬된 데이터에 삽입 정렬을 적용하는 구조라서 효율이 높다.

### 3.3 쉘 정렬의 기본 간격과 Knuth 수열의 성능 차이

| n | 기본 | Knuth | Knuth의 감소율 |
|---:|---:|---:|---:|
| 1,000 | 15,837 | 13,609 | 14.1% |
| 2,000 | 35,620 | 31,914 | 10.4% |
| 4,000 | 85,372 | 74,204 | 13.1% |
| 8,000 | 207,022 | 192,139 | 7.2% |
| 16,000 | 483,028 | 419,306 | 13.2% |
| 20,000 | 607,353 | 543,126 | 10.6% |

```
※ 감소율(%) = (기본 간격 비교 횟수 − Knuth 비교 횟수) ÷ 기본 간격 비교 횟수 × 100
```

- Knuth 수열은 **모든 크기에서** 기본 간격보다 비교 횟수가 적었고, 감소율은 7~14% 수준이었다.
- 차이는 삽입 정렬 대비 쉘 정렬의 이득(수십~수백 배)에 비하면 작다. 쉘 정렬을 쓰는 것 자체가 가장 큰 효과이고, Knuth 수열은 그 위에서 추가로 성능을 다듬는 요소임을 알 수 있다.
- n당 비교 횟수로 보면 n=20,000에서 기본은 약 30.4회, Knuth는 약 27.2회다. 이 값은 n이 커질수록 기본 간격 쪽이 더 빠르게 커지는 경향을 보인다. 다만 이번 실험은 한 번의 무작위 데이터이고 n 범위가 제한적이어서, 격차가 계속 벌어진다고 단정하기는 어렵다.

### 3.4 간격 수열이 쉘 정렬 성능에 영향을 미치는 이유

**기본 간격(n/2, n/4, …)의 한계**
- n이 2의 거듭제곱이면 간격이 모두 짝수(마지막 1 제외)다. 예를 들어 n=16,000의 첫 간격은 8,000이다. 간격이 짝수이면 짝수 위치 원소와 홀수 위치 원소가 서로 다른 부분 배열에 속해서 **마지막 h=1 단계 이전까지 섞이지 않는다.**  
  그러면 앞 단계에서 정렬해 놓은 결과가 다음 단계에서 충분히 활용되지 못하고, 홀수·짝수 위치가 처음 만나는 h=1 단계에서 많은 비교가 한꺼번에 발생한다.
- 또한 간격이 절반씩 줄기 때문에 서로 배수 관계가 되어 앞 단계와 겹치는 비교가 생겨 정보 전달 효율이 떨어진다.

**Knuth 수열(1, 4, 13, 40, …)의 장점**
- 간격이 약 3배씩 줄고 서로 배수 관계가 아니다(1, 4, 13, 40…은 3h+1 꼴). 그래서 단계마다 **다른 위치의 원소들이 서로 섞여** 비교된다.
- 각 단계에서 거의 정렬된 상태가 다음 단계로 잘 전달되어, 마지막 h=1 단계에서 남은 역전이 적다.
- 단계 수도 적다. n=20,000에서 Knuth는 9,841부터 1까지 9단계(9841, 3280, 1093, 364, 121, 40, 13, 4, 1)로 끝나는 반면, 기본 간격은 14단계(10,000 → 1)를 거친다. 각 단계마다 최소 약 n번의 비교가 들기 때문에, 단계 수가 적으면 고정 비용이 줄어든다.  

- 이런 이유로 과제에서 Knuth 수열이 모든 크기에서 더 적은 비교 횟수를 보였다. 이론적으로도 기본 간격의 최악 복잡도는 O(n²), Knuth 수열은 O(n^1.5)로 알려져 있다.

## 4. 결론

1. 삽입 정렬은 n이 2배일 때 비교 횟수가 약 4배로 늘어 O(n²) 특성을 보였고, 비교 횟수는 n²/4에 가까웠다.
2. 쉘 정렬은 증가 배율이 약 2.2~2.6배에 그쳐 훨씬 완만하다. n=20,000에서 삽입 정렬 대비 약 165~185배 적은 비교로 정렬했다. 큰 간격에서 멀리 이동시켜 역전을 먼저 줄이기 때문이다.
3. 같은 쉘 정렬이라도 간격에 따라 성능이 달랐다. Knuth 수열이 모든 크기에서 기본 간격보다 7~14% 적게 비교했다.
4. 따라서 정렬 성능은 알고리즘의 구조(간격을 두고 먼저 정렬하는가)가 가장 크게 좌우하고, 간격 수열의 선택이 그다음으로 영향을 준다고 할 수 있다.
