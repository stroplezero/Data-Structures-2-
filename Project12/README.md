# 퀵 정렬 피벗 선택 방법에 따른 비교 횟수 분석

## 1. 개요
- 무작위 정수(중복 허용)를 오름차순으로 정렬하고, 피벗 선택 방법 세 가지의 **숫자 비교 횟수**를 측정했다.
- 데이터 크기: n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- 같은 크기에서는 세 방법이 동일한 원본의 복사본을 사용했다.
- 피벗 선택 함수만 다르고, 나머지 분할 알고리즘은 모두 같다.
- 비교 횟수에는 분할 중 `원소 vs 피벗` 비교와 Median-of-Three의 중앙값 결정 비교(2~3회)를 포함했다. 인덱스 검사, 난수 생성, 데이터 이동은 제외했다.
- 모든 결과에서 오름차순 정렬이 올바른지 확인했다.

## 3. 데이터 크기 증가에 따른 변화
- 세 방법 모두 n이 커질수록 비교 횟수가 **약 2배보다 조금 더 많이** 늘었다. 예를 들어 First는 1,000개에서 11,865회, 2,000개에서 27,215회로 약 2.3배가 되었다.
- 이는 평균 시간복잡도가 **O(n log n)** 이기 때문이다. n을 2배로 하면 n이 2배가 되고 log n도 약간 커지므로 2배를 조금 넘는다.
- n·log₂n으로 나눈 값이 세 방법 모두 대략 1.2~1.3 안에서 유지되었다. 이는 어느 방법이든 무작위 데이터에서는 O(n log n) 범위에 있고, 최악인 O(n²)로 가지 않았다는 뜻이다.

## 4. 피벗 선택 방법별 성능 차이

### 실험에서 관찰한 것
- **Median-3**은 6개 크기 중 5개(2,000 ~ 8,000, 20,000)에서 First보다 비교 횟수가 적었다. 8,000개에서는 First보다 약 6.5% 적었다.
- 하지만 **16,000개에서는 Median-3이 가장 많았다**(First보다 약 6.2% 많음). 1,000개에서도 사실상 차이가 없었다(0.2%).
- **Random**은 First와 Median-3 사이에서 오르내렸다. 1,000개, 4,000개, 16,000개에서는 First보다 많았고, 나머지에서는 적었다.
- 전체적으로 세 방법의 차이는 대부분 **약 4~6% 이내**로 크지 않았다.

### 한계: 이 차이가 "방법의 차이"인지 "우연"인지
- 이 결과는 **크기마다 데이터 1세트, 실행 1회**만 측정한 것이다. 크기마다 데이터가 새로 생성되었다.
- 퀵 정렬의 비교 횟수는 데이터에 따라 크게 흔들린다. 비교 횟수의 표준편차는 대략 0.65n 수준으로 알려져 있다. 이 값은 n=16,000에서 약 1만 회이고, First와 Median-3의 차이(약 1.7만 회)는 이 흔들림과 비슷한 크기이다.
- 따라서 **한 번의 측정으로 "어느 방법이 더 낫다"고 단정할 수 없다.** 특히 16,000개에서 Median-3이 불리하게 나온 것은 이론적 결함이 아니라 데이터에 따른 우연으로 보는 것이 타당하다.
- 신뢰할 수 있는 결론을 얻으려면 크기마다 데이터를 수십~수백 번 바꿔 평균을 내야 한다.

## 5. 피벗 선택이 분할과 비교 횟수에 영향을 주는 이유
퀵 정렬은 피벗을 기준으로 구간을 둘로 나눈다. 구간 길이가 m이면 분할에 약 m번의 비교가 든다. 따라서 전체 비교 횟수는 **분할이 얼마나 균등하게 되느냐**로 결정된다.

- **균등한 분할(피벗이 중앙값에 가까움)**: 재귀 깊이가 약 log₂n이 되고, 각 단계의 비교 합이 n 안팎이므로 총 비교는 약 n·log₂n이다.
- **치우친 분할(피벗이 최솟값·최댓값에 가까움)**: 한쪽 구간이 거의 줄지 않아 깊이가 n에 가까워지고 총 비교는 O(n²)이 된다.

| 방법 | 분할에 미치는 영향 |
|---|---|
| First | 피벗이 데이터와 무관하게 고정된 위치이다. 무작위 데이터에서는 그 값이 임의의 값이라 평균적으로는 괜찮다. 하지만 **이미 정렬되었거나 거의 정렬된 입력**에서는 항상 최솟값을 고르게 되어 O(n²)이 된다. |
| Random | 입력 순서와 무관하게 피벗을 고르므로 특정 입력이 일관되게 나쁜 결과를 내지 않는다. 다만 매번 분할 품질이 우연에 의존하므로 평균적으로는 First와 이론상 같다(약 1.39·n·log₂n). |
| Median-3 | 세 값의 중앙값은 최솟값·최댓값이 될 가능성이 낮다. 따라서 극단적으로 치우친 분할이 줄고, 평균 약 **1.19·n·log₂n**으로 이론상 First·Random보다 약 15% 적다. 대신 중앙값을 정하는 비교가 분할마다 2~3회 추가된다. |

실험 결과의 n·log₂n 배율은 First와 Random이 약 1.19~1.28, Median-3이 약 1.17~1.32로 나왔다. First와 Random의 평균은 이론값(약 1.39)보다 낮게 나왔다. 이는 이 구현이 Hoare 방식 분할이고, 이론값 계산이 사용하는 구현과 상수가 다르기 때문이다.  
즉 **절대 수치는 구현에 따라 달라지지만 방법 사이의 순서와 원리는 같다.**

Median-3의 추가 비교(분할당 2~3회)는 작은 구간에서 상대적으로 부담이 된다. 구간이 작을수록 분할 하나가 하는 일 자체가 적기 때문이다. 이런 이유로 이득이 이론값만큼 크게 드러나지 않을 수 있다.

## 6. 어떤 방법이 효과적이었는가

1. **평균 비교 횟수만 보면 Median-of-Three가 가장 유리한 경향**을 보였다. 6개 크기 중 5개에서 First보다 적었고, 20,000개에서는 가장 적었다(340,554회). 이는 이론적 예측(약 15% 감소)과 방향이 같다.
2. 그러나 이 실험의 차이는 크기가 4~6% 정도라서 **통계적으로 확실하다고 말하기는 어렵다.** 16,000개의 반대 결과가 그 증거이다.
3. **First**는 무작위 데이터에서는 나쁘지 않았지만, 입력 순서에 취약하다는 구조적 약점이 있다. 이 실험은 무작위 데이터만 썼으므로 그 약점이 드러나지 않았다.
4. **Random**은 평균 성능이 First와 비슷했다. 성능이 가장 좋지는 않았지만, 입력 패턴에 상관없이 최악의 경우를 피할 수 있는 안정성이 장점이다.

**종합**: 무작위 데이터에서는 세 방법 모두 O(n log n)으로 동작했고 차이는 크지 않았다. 그중 Median-of-Three가 이론과 실험 모두에서 가장 효율적이고 분할도 안정적이었다. 실제로 쓸 때는 정렬된 입력에서도 안전한 Median-of-Three나 Random이 First보다 낫다. 
더 확실한 결론을 위해서는 반복 측정과 정렬된·역순 데이터 같은 다른 입력 조건에서의 실험이 필요하다.
