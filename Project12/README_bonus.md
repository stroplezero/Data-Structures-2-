# [보너스] 재귀적 퀵 정렬과 반복적 퀵 정렬의 실행시간 비교

## 1. 조건
- 데이터 크기: 10,000개 (무작위 정수, 중복 허용)
- 피벗 선택: Median-of-Three
- 두 방법은 **같은 원본 데이터, 같은 피벗 선택, 같은 분할(partition) 함수**를 사용하고, 정렬을 호출하는 구조만 다르다.
  - 재귀적: 분할 후 왼쪽·오른쪽 구간을 함수 재귀 호출로 처리한다.
  - 반복적: 처리할 구간 `(lo, hi)`를 배열로 만든 스택에 넣고, 꺼내서 분할하는 `while` 반복문으로 처리한다. 큰 구간을 먼저 넣고 작은 구간을 나중에 넣어 먼저 처리한다.
- 측정 범위: 정렬 함수 호출만 측정한다. 데이터 생성, 배열 복사, 정렬 결과 검증, 출력은 제외했다.
- 실행시간이 매우 짧아 **200회 반복 측정한 평균**을 사용했고, 단위는 두 방법 모두 ms이다. 측정 전에 각 방법을 한 번씩 실행해 워밍업했다.
- 시간은 `QueryPerformanceCounter`로 측정했다.

## 2. 결과

```
Data Size : 10000
Pivot     : Median-of-Three
(평균, 200회 반복)

Recursive Quick Sort : 1.3379 ms
Iterative Quick Sort : 1.3624 ms
```
> 실제 실행 결과는 [7. 실제 실행 결과](#7-실제-실행-결과)에 있다.

| 방법 | 평균 실행시간 (ms) |
|---|---:|
| 재귀적 | 1.3379 |
| 반복적 | 1.3624 |
| 차이 (반복 − 재귀) | 0.0245 |

반복적 방법이 재귀적 방법보다 **0.0245 ms, 약 1.8% 더 오래 걸렸다.**

## 3. 실행시간 차이 분석
- 두 방법의 실행시간은 거의 같았다. 차이는 0.0245 ms로, 재귀적 방법 시간의 약 1.8%에 불과하다.
- 이 실험에서는 반복적 방법이 약간 느리게 나왔다. 스택을 직접 쓰면 함수 호출 비용이 없어 더 빠를 것이라고 예상할 수 있지만, 이번 결과는 그렇지 않았다.
- 이 값은 200회 반복 평균이므로 타이머 정밀도나 순간적인 잡음의 영향은 줄었다. 다만 200회 모두 같은 원본 데이터로 한 번의 프로그램 실행 안에서 측정했다. 프로그램을 다시 실행하면 데이터와 CPU 상태가 달라져 결과가 조금씩 달라질 수 있다.
- 따라서 "반복적 방법이 느리다"고 단정하기보다 "두 방법의 성능 차이는 매우 작다" 가 이 결과에 맞는 결론이다.

## 4. 차이가 발생한 이유

1. **실행 시간의 대부분은 두 방법이 공통으로 쓰는 작업이다.**
   - 두 방법은 같은 `partition()`과 Median-of-Three 피벗 선택을 쓴다. 분할 횟수와 구간 크기, 비교 횟수와 원소 교환 횟수가 같다.
   - 재귀냐 반복이냐는 "다음에 처리할 구간을 어떻게 관리하느냐"만 다르다. 그래서 전체 시간에서 차지하는 비중이 작고, 시간 차이도 작게 나타난다.
2. **재귀적 방법의 추가 비용**: 분할마다 함수 호출이 일어나고, 호출마다 인자와 복귀 주소 등을 담은 스택 프레임이 만들어졌다 사라진다.
3. **반복적 방법의 추가 비용**: 구간을 배열 스택에 넣고(push) 꺼내는(pop) 연산이 분할마다 있다. 한 번의 분할에 구간 2개(4개의 값)를 저장하고, 큰 구간과 작은 구간 중 어느 쪽을 먼저 넣을지 비교하는 조건문도 있다. 재귀 방식에는 이 부분이 없다.
4. 따라서 두 방법은 각각 다른 종류의 부가 비용(호출·복귀 vs. 스택 저장·조건 분기)을 가진다. 이번 결과에서는 반복적 방법의 부가 비용이 근소하게 더 컸던 것으로 해석할 수 있다.

## 5. 결론
- 10,000개 데이터에서 재귀적 퀵 정렬은 1.3379 ms, 반복적 퀵 정렬은 1.3624 ms로 **차이가 약 1.8%인 거의 같은 성능**이었다.
- 같은 분할 알고리즘을 쓰므로 실행시간의 대부분은 분할 작업이 차지하고, 재귀와 반복의 구조 차이는 전체 시간에 큰 영향을 주지 않았다.
- 반복적 구현을 하는 의미는 속도 향상보다는 스택을 직접 관리한다는 점에 있다. 이 실험에서 속도 면의 이점은 확인되지 않았다.
