# 퀵 정렬 vs AVL 트리 정렬 성능 비교

## 1. 개요

| 항목 | 내용 |
|---|---|
| 소스 파일 | `sort_compare.c` |
| 데이터 | 0~99,999 범위 무작위 정수 (중복 허용), n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000 |
| 퀵 정렬 | **피벗: Median-of-3** (첫·중간·끝 원소의 중앙값). 정렬 후 삽입·삭제는 정렬 배열에서 선형 탐색 + 원소 이동 |
| AVL 트리 | 같은 데이터를 AVL 트리에 삽입. 중복은 노드의 `cnt`로 저장. 삽입·삭제는 트리에서 직접 수행하고 회전으로 균형 복구 |
| 삽입·삭제 | n의 20%(n=1,000 → 200회 … n=20,000 → 4,000회). 짝수면 삽입, 홀수면 삭제. 값이 없으면 삭제하지 않음. 두 자료구조에 같은 연산·값을 적용 |
| 검증 | 모든 크기에서 최종 배열과 AVL 중위 순회 결과가 일치 (`Result match: OK`) |

### 측정 기준
- **총 수행시간**: 정렬 시작 ~ 마지막 삽입·삭제 완료 (난수 생성·출력 제외, 1회 실행값)
- **비교 횟수**: 데이터 값 비교만 집계 (정렬, 삽입 위치 탐색, 삭제 대상 탐색). AVL의 균형 인수 비교는 제외하고, 노드 방문 시 3방향 비교(`<`, `>`, `==`)는 1회로 계산
- **데이터 이동 횟수**: 값의 복사·대입 횟수. 퀵 정렬의 `swap` 1회는 3회로 계산. AVL의 포인터 연결 변경과 회전은 제외하고, 노드 `key` 대입과 `cnt` 증감은 포함
- **메모리**: 자료구조 + 보조 공간의 최대 사용량. 배열은 `4B × 최대 원소 수` + 재귀 스택 근사값, AVL은 `sizeof(Node)(24B) × 최대 노드 수` + 재귀 스택 근사값 (근사치)

## 3. 비교·분석

### 3.1 총 수행시간과 비교 횟수
정렬 단계만 보면 두 방법의 비교 횟수는 비슷하다. 둘 다 O(n log n)이고, n=20,000에서 퀵 정렬의 정렬 단계는 대략 수십만 번 수준이다(이전 과제 결과 참고). 이 값은 AVL 전체 비교 횟수 316,011과 같은 자릿수이다. 
그런데 전체 과정의 비교 횟수는 퀵 정렬이 42,072,373회로 AVL보다 약 133배 많았다. 차이는 거의 전부 **삽입·삭제 단계**에서 생긴다는 것을 알 수 있다.

- 정렬 배열은 삽입 위치와 삭제 대상을 **선형 탐색**으로 찾는다. 연산 한 번에 평균 O(n)번 비교하므로, 연산 횟수가 n의 20%일 때 전체는 O(n²)이다.
- AVL 트리는 트리 높이(약 log₂n)만큼만 내려가므로 연산당 O(log n)이다. 이진 탐색이 가능한 정렬 상태가 트리 구조로 유지되기 때문이다.

시간은 비교 횟수만큼 크게 벌어지지는 않았다. 비교 횟수 차이는 11배에서 133배로 커졌지만, 시간 차이는 0.5배에서 5.3배로 커졌다. 이유는 다음과 같다.
- 배열의 선형 탐색과 원소 이동은 **연속된 메모리를 순서대로 접근**하므로 캐시 효율이 높고, 연산 하나의 비용이 매우 작다.
- AVL은 비교 횟수는 적지만 `malloc` 호출, 포인터 추적, 회전과 높이 갱신이라는 **연산당 상수 비용**이 크다. 포인터를 따라가는 접근은 캐시에 불리하다.

따라서 n이 작을 때는 AVL의 상수 비용이 이득을 상쇄해 퀵 정렬이 더 빨랐다(n=1,000에서 AVL이 약 2배 느림). n=2,000에서 두 방법이 거의 같아졌고, n=4,000부터 AVL이 빨라졌다. 즉 **교차점은 n≈2,000~4,000 부근**이라 할 수 있다.

### 3.2 데이터 이동 횟수
이동 횟수 차이가 가장 극단적이다. n=20,000에서 퀵 정렬은 25,572,094회, AVL은 22,378회로 약 1,143배 차이다.

- **배열**은 중간에 삽입하거나 삭제하면 뒤쪽 원소를 전부 한 칸씩 밀거나 당겨야 한다. 연산당 평균 약 n/2번 이동하며, 위치가 앞쪽일수록 많이 이동한다. 이 비용이 이동 횟수의 대부분이다.
- **AVL**은 삽입 시 새 노드의 `key`를 한 번 대입하고, 중복이면 `cnt`만 바꾼다. 포인터만 바꾸는 회전은 이동으로 세지 않으므로 이동 횟수가 연산 횟수 수준(n=20,000에서 약 2만 회)에 머문다.

AVL의 이동 횟수는 n이 20배 늘 때 약 20배(1,111 → 22,378)만 늘었고, 퀵 정렬은 약 380배(67,191 → 25,572,094) 늘었다. AVL은 **n에 선형, 배열은 n²에 가깝게** 늘어난다는 구조적 차이가 그대로 나타났다.

### 3.3 메모리 사용량
메모리는 반대로 **배열이 훨씬 유리**했고, 모든 크기에서 AVL이 약 7.1~7.5배 더 많이 썼다(n=20,000에서 87,592B vs 621,148B).

- 배열은 원소마다 `int` 4바이트만 쓰고, 정렬에 필요한 추가 공간은 재귀 스택(Median3 피벗이라 깊이가 얕음) 정도이다.
- AVL 노드는 `key`, `cnt`, `height`(각 4B)와 자식 포인터 2개(각 8B)로 24바이트이다. 데이터 자체의 4바이트 대비 오버헤드가 6배이고, 노드마다 `malloc` 관리 비용이 추가된다.
- 배율이 크기와 무관하게 거의 일정한 것은 둘 다 원소 수에 비례해 늘기 때문이다. 노드 크기가 24B로 고정이라 배열 대비 비율이 일정하다.
- 중복이 `cnt`로 합쳐지므로 중복이 많은 데이터에서는 AVL의 메모리가 다소 줄겠지만, 이번 실험은 값 범위(10만)에 비해 n이 작아 중복이 적어서 효과가 작았다.

### 3.4 데이터 크기 증가에 따른 성능 변화
n이 1,000에서 20,000으로 20배 커졌을 때 증가 배율은 다음과 같다.

| 지표 | 퀵 정렬 | AVL |
|---|---|---|
| 시간 | 약 292배 (0.27 → 78.2 ms) | 약 28배 (0.53 → 14.8 ms) |
| 비교 횟수 | 약 346배 | 약 29배 |
| 데이터 이동 | 약 380배 | 약 20배 |
| 메모리 | 약 17.6배 | 약 17.5배 |

- 퀵 정렬 쪽 시간·비교·이동은 n이 20배일 때 약 300배 안팎으로, n²(=400배)에 가까운 증가이다. 연산 수도 n에 비례해 늘어나기 때문에, 연산당 O(n) × 연산 수 O(n) 구조가 그대로 드러난다.
- AVL 쪽은 n log n에 가까운 증가(20배 × log 비율 ≈ 약 28배)를 보였다.
- 메모리는 두 방법 모두 n에 비례해 선형으로 늘었다.
- 결과적으로 **n이 클수록 AVL의 시간 이점이 커져서**, 시간 배율이 0.5배에서 5.3배로 뒤집혔고 계속 벌어지는 추세이다.

### 3.5 삽입·삭제가 반복되는 환경에서 유리한 자료구조
**삽입·삭제가 반복되는 환경에서는 AVL 트리가 유리하다.** 이유는 다음과 같다.

1. **탐색 비용**: 배열의 선형 탐색은 O(n)이고, AVL은 높이가 항상 O(log n)으로 보장되어 O(log n)이다.
2. **이동 비용**: 배열은 연속 저장을 유지하려고 원소를 밀고 당기지만, AVL은 포인터만 바꾸므로 값 이동이 거의 없다. 실험에서 이동 횟수가 1,000배 이상 차이가 났다.
3. **정렬 상태 유지**: AVL은 삽입·삭제 후에도 별도 재정렬 없이 중위 순회만으로 오름차순을 얻는다. 균형은 회전으로 O(log n) 안에 복구된다.
4. **확장성**: n과 연산 수가 커질수록 배열과의 격차가 벌어지므로 대량 데이터일수록 이점이 크다.

다만 다음과 같은 경우는 **배열(퀵 정렬)이 나았다.**
- 데이터가 작거나(이번 실험에서는 n≈2,000 이하), 삽입·삭제가 거의 없고 한 번 정렬한 뒤 조회만 하는 경우. 상수 비용이 작고 캐시 효율이 좋았다.
- 메모리가 부족한 환경. AVL은 약 7배의 메모리를 쓴다.
- 인덱스로 임의 접근해야 하는 경우. 배열은 O(1), AVL은 O(log n)이다.

## 4. 결론
- 정렬 자체는 퀵 정렬이 가볍고 빠르지만, 정렬 이후 **삽입·삭제가 반복되면 배열의 O(n) 탐색과 O(n) 이동 때문에 비용이 n²에 가깝게 증가**한다.
- AVL 트리는 **메모리를 약 7배 더 쓰고 작은 n에서는 상수 비용 때문에 느리지만**, 비교 횟수 133배, 이동 횟수 1,143배, 시간 5.3배(n=20,000)로 더 효율적이며 n이 커질수록 격차가 커진다.
- 따라서 삽입·삭제가 잦고 데이터가 큰 환경에는 AVL 트리를, 데이터가 작거나 조회 중심이고 메모리가 제한된 환경에는 정렬 배열을 선택하는 것이 합리적이다.

## 5. 유의사항
- 시간은 **1회 실행값**이어서 실행 환경과 시점에 따라 달라진다. 특히 작은 n의 시간 비교(n=1,000~2,000)는 오차가 클 수 있다. 교차점은 대략적인 위치로 보는 것이 좋다.
- 메모리는 구조체 크기와 재귀 깊이로 계산한 **근사치**이다. 실제 할당자 오버헤드와 패딩은 반영하지 않았다.
- 무작위 데이터 기준 결과이다. 이미 정렬된 입력 등 다른 분포에서는 달라질 수 있다.
