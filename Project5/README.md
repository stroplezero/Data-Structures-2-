# 순차 탐색과 이진 탐색 트리 탐색의 비교

## 1. 개요

- 0~1,000 사이의 **서로 다른 정수 100개**를 발생 순서대로 정수 배열과 BST(연결 구조)에 저장했다.
- 별도로 0~1,000 사이의 탐색 대상 50개를 생성하고, 같은 키에 대해 순차 탐색과 BST 탐색을 모두 수행했다.
- 성능 지표는 **숫자 비교 횟수**이다.

### 비교 횟수 계산 기준
| 항목 | 기준 |
|---|---|
| 순차 탐색 | 배열 원소와 비교할 때마다 1회 (실패 시 100회) |
| BST 탐색 | 방문한 노드마다 1회. 실패 시 NULL에 도달할 때까지 거친 노드 수 |
| BST 생성 | 삽입 위치를 찾기 위해 기존 노드와 비교할 때마다 1회 |

## 2. 실행 결과 요약

| 항목 | 순차 탐색 | BST 탐색 |
|---|---|---|
| 탐색 횟수 | 50 | 50 |
| **총 비교 횟수** | **4,917** | **364** |
| **평균 비교 횟수** | **98.34** | **7.28** |
| 최소 / 최대 | 70 / 100 | 3 / 11 |
| 구조 생성 비용 | 0 (배열에 저장만 함) | **591** |
| **생성 비용 포함 합계** | **4,917** | **955** (591 + 364) |

- 탐색 성공 7개, 실패 43개
- BST 높이: 12 (노드 100개의 이상적인 균형 트리 높이는 7)

> 실제 실행 화면은 [6. 참고: 실제 실행 화면](#6-참고-실제-실행-화면)에서 확인할 수 있다.

## 3. 분석

### 3.1 두 탐색 방법의 성능 차이
BST 탐색의 총 비교 횟수는 364회로, 순차 탐색(4,917회)의 약 **7.4%** 수준이다. 평균은 7.28회 대 98.34회로 약 **13.5배** 차이가 난다.

이유는 탐색 범위가 줄어드는 방식이 다르기 때문이다.
- 순차 탐색은 한 번 비교해도 후보가 1개만 줄어든다. 최악에는 n = 100번 비교하며, 시간 복잡도는 O(n)이다.
- BST는 한 번 비교할 때마다 왼쪽 또는 오른쪽 서브트리 하나를 통째로 버린다. BST 탐색의 비교 횟수는 탐색 경로의 길이, 즉 도달한 노드의 깊이에 비례한다.

**실패 탐색 비중이 높다는 점도 결과에 영향을 주었다.** 50개 중 43개(86%)가 실패였다. 100개 값이 0~1,000 범위에서 뽑혔으므로 임의의 키가 존재할 확률은 약 10%에 불과하기 때문이다.
- 순차 탐색은 실패하면 항상 100회를 모두 비교한다. 43개 실패만으로 4,300회로, 총합 4,917회의 87%를 차지한다. 성공 7건의 비교는 70~100회(평균 약 88.1회)였다.
- BST는 성공 7건 평균이 약 8.29회, 실패 43건 평균이 약 7.12회였다. 실패한 탐색은 NULL에 닿을 때까지 내려가므로 성공한 탐색보다 적게 비교한 경우도 있다. 키가 트리의 얕은 위치에서 빈 자식을 만나면 일찍 끝나기 때문이다.

이 실험에서는 성공 비율이 낮아서 순차 탐색의 불리함이 더 크게 나타났다. 성공 비율이 높으면 순차 탐색의 평균은 절반(약 50회) 근처까지 내려가겠지만, 그래도 BST보다는 훨씬 많다.

### 3.2 BST 생성 비용을 고려한 비교
배열은 값을 순서대로 저장만 하면 되지만, BST는 삽입할 때마다 위치를 찾기 위해 비교해야 한다. 100개를 삽입하는 데 **591회**가 필요했다(첫 노드는 비교 없이 루트가 되므로 99번의 삽입에서 평균 약 5.97회).

| 구분 | 순차 탐색 | BST |
|---|---|---|
| 구조 생성 | 0 | 591 |
| 50회 탐색 | 4,917 | 364 |
| **합계** | **4,917** | **955** |

생성 비용을 포함해도 BST가 **3,962회 적고**, 합계 기준으로 약 **5.1배** 효율적이다. 다만 탐색만 비교한 13.5배보다 격차는 줄었다. 생성 비용이 전체 BST 비용의 62%(591/955)나 되기 때문이다.

**손익분기점:** 탐색 1회당 절약량은 98.34 − 7.28 ≈ 91.06회이다. 생성 비용 591회를 회수하려면 591 / 91.06 ≈ **6.5회**, 즉 **약 7회 이상 탐색**하면 BST가 이득이다. 이번 실험은 50회를 탐색했으므로 충분히 이득을 본 사례이다.

반대로 다음 경우에는 BST 생성 비용이 이득이 되지 않을 수 있다.
- 탐색을 몇 번 하지 않고 데이터를 버리는 경우(1회성 탐색)
- 데이터가 자주 바뀌어 구조를 계속 새로 만들어야 하는 경우

탐색을 반복할수록 생성 비용은 탐색 횟수로 나뉘어 상대적으로 작아지고, BST 생성 비용이 이득이 된다.

### 3.3 트리 구조에 따른 탐색 성능
BST의 탐색 비용은 **트리의 높이와 노드의 깊이**로 결정되며, 트리 모양은 **삽입 순서**가 정한다. 같은 100개 값이라도 순서가 다르면 모양이 달라진다.

- **이번 실험 (무작위 순서 삽입):** 높이가 12로, 균형 트리의 이상적인 높이 7보다 컸다. 완전히 균형 잡히지는 않았으나 극단적으로 치우치지도 않았다. 그 결과 평균 비교는 7.28회, 최대는 11회였다. 무작위로 삽입하면 대체로 log n에 가까운 성능이 나온다.
- **최선(균형 트리):** 높이가 약 log₂(n+1)이다. 100개이면 7이며, 탐색은 최대 7회 정도에 끝난다.
- **최악(정렬된 순서로 삽입):** 오름차순이나 내림차순으로 넣으면 모든 노드가 한쪽 자식만 갖는 **연결 리스트 모양**이 된다. 높이가 100이고, 탐색은 순차 탐색과 같은 O(n)으로 떨어진다. 생성 비용도 1 + 2 + … + 99 = 4,950회로 급증한다. 이번 실험의 591회와 비교하면 약 8배이다. 이 경우 BST는 비용만 더 들고 이점이 없다.

높이는 12지만 평균 비교는 7.28회에 그친 것은, 깊은 가지에 있는 노드가 일부일 뿐 대부분의 탐색은 더 얕은 곳에서 끝났기 때문이다. 트리가 한쪽으로 치우칠수록 깊은 가지가 늘어나 평균도 나빠진다.

정리하면, 같은 100개의 값이라도 삽입 순서에 따라 트리의 높이와 탐색 비용이 크게 달라진다. 따라서 BST의 성능은 데이터를 삽입하는 순서에 따라 달라진다.

## 4. 결론

1. BST 탐색은 평균 7.28회로, 순차 탐색(98.34회)보다 약 13.5배 적게 비교했다.
2. BST 생성 비용 591회를 포함해도 합계 955회로 순차 탐색(4,917회)보다 약 5.1배 효율적이었다. 약 7회 이상 탐색하면 생성 비용을 회수한다.
3. BST의 이점은 트리가 균형에 가까울 때 성립한다. 삽입 순서가 나쁘면 BST의 높이가 n에 가까워져 순차 탐색 수준으로 떨어진다.
4. 이번 실험은 탐색 대상의 86%가 실패였기 때문에 순차 탐색의 불리함이 크게 나타났다. 실행할 때마다(난수 시드에 따라) 수치는 달라질 수 있으나, 경향은 같다.
