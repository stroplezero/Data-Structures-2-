# 최소 비용 신장 트리(MST) 알고리즘 비교

정점 50개의 가중치 무방향 연결 그래프(희소 E=100, 밀집 E=600)에 대해 **인접 리스트 + Kruskal**과 **인접 행렬 + Prim**의 메모리 사용량과 실행시간을 비교한 과제이다.

## 1. 파일 구성

| 파일 | 설명 |
|---|---|
| `mst_compare.c` | 그래프 생성, Kruskal, Prim, 성능 측정, 결과 출력 (C) |
| `README.md` | 실험 결과와 분석 (이 문서) |

## 2. 소스코드

[mst_compare.c](https://github.com/stroplezero/Data-Structures-2-/blob/main/Project8/mst_compare.c)

시간 측정은 Windows의 `QueryPerformanceCounter`를 사용한다.

## 3. 구현 요약

- **그래프 생성**: 임의의 신장 트리(간선 49개)를 먼저 만들어 연결성을 보장하고, 자기 루프와 중복 간선이 생기지 않게 나머지 간선을 추가한다. 가중치는 1~100의 정수이다. 마지막으로 DFS로 연결 여부를 한 번 더 확인하고, 연결되지 않았으면 다시 생성한다.
- **동일 그래프 사용**: 희소/밀집 그래프를 각각 한 번만 만들고, 같은 간선 목록에서 인접 리스트와 인접 행렬을 모두 만든다. 즉, Case 1과 3, Case 2와 4는 정점·간선·가중치가 같고 표현 방법과 알고리즘만 다르다.
- **Kruskal (인접 리스트)**: 인접 리스트에서 간선 배열을 만든 뒤(무방향 간선은 리스트에 두 번 들어 있으므로 한 번씩만 담는다) `qsort`로 가중치 순 정렬하고, Union-Find로 사이클을 판별한다. 선택한 간선이 49개가 되면 종료한다.
- **Prim (인접 행렬)**: 시작 정점 0에서 `key[]`, `parent[]`, `inMST[]` 배열을 두고, 매 단계마다 선형 탐색으로 key가 가장 작은 정점을 선택한다. 시간 복잡도는 O(V²)이다.
- **메모리 측정**: `sizeof`로 직접 계산한다. 그래프 표현, 알고리즘 보조 자료구조, 결과 MST 배열을 포함하고 난수 생성·출력용 메모리는 제외한다.
- **시간 측정**: 그래프 생성이 끝난 뒤 MST 계산 시작부터 종료까지만 재고, 4개 Case 모두 같은 방법과 단위(ms)를 사용한다. 각 Case는 1회 측정했다. 난수 시드를 `time(NULL)`로 정하므로 실행할 때마다 그래프가 달라지며, 아래 MST 비용과 시간은 한 번 실행한 결과이다(메모리는 정점·간선 수가 고정이라 매번 같다).

## 4. 결과

| Case | 그래프 | 표현 | 알고리즘 | MST 간선 수 | MST 비용 | 메모리 (Byte) | 실행시간 (ms) |
|---|---|---|---|---|---|---|---|
| 1 | Sparse (V=50, E=100) | 인접 리스트 | Kruskal | 49 | 1399 | 5,788 | 0.065700 |
| 2 | Dense (V=50, E=600) | 인접 리스트 | Kruskal | 49 | 225 | 27,788 | 0.236500 |
| 3 | Sparse (V=50, E=100) | 인접 행렬 | Prim | 49 | 1399 | 11,188 | 0.087900 |
| 4 | Dense (V=50, E=600) | 인접 행렬 | Prim | 49 | 225 | 11,188 | 0.058100 |

> 실제 실행 결과는 [8. 참고자료](#8-참고자료)에 있다.

### 결과 검증
- 4개 Case 모두 MST 간선 수가 49(= V−1)이다.
- 같은 그래프에서 Kruskal과 Prim의 MST 비용이 일치한다(희소 1399, 밀집 225).
- 두 알고리즘은 간선을 고르는 순서가 다르다. Kruskal은 가중치가 작은 간선부터, Prim은 정점 0에서 뻗어 나가며 고른다. 가중치가 같은 간선이 있으면 선택된 간선 집합이 다를 수도 있지만, MST 비용은 항상 같아야 하므로 비용이 일치하면 정상이다.
- 밀집 그래프의 MST 비용(225)이 희소 그래프(1399)보다 훨씬 작은 이유는 간선이 6배 많아 가중치가 작은 간선을 고를 선택지가 늘기 때문이다. MST 간선 가중치의 평균은 밀집이 약 4.6(225÷49), 희소가 약 28.6(1399÷49)이다.

## 5. 분석

### 5.1 메모리 사용량: 인접 리스트 vs 인접 행렬

`sizeof(Node)`=16B, `sizeof(Edge)`=12B, `int`=4B, 포인터=8B(64비트 환경) 기준으로 항목별 계산한 표이다. 32비트 환경에서는 포인터가 4B라 리스트 쪽 값이 달라진다.

| 항목 | Case 1 | Case 2 | Case 3 / 4 |
|---|---|---|---|
| 그래프 표현 | 3,600 (헤드 400 + 노드 2×100×16) | 19,600 (헤드 400 + 노드 2×600×16) | 10,000 (50×50×4) |
| 알고리즘 보조 구조 | 1,600 (간선 배열 100×12 + Union-Find 400) | 7,600 (간선 배열 600×12 + Union-Find 400) | 600 (key, parent, inMST 각 50×4) |
| 결과 MST 배열 | 588 (49×12) | 588 | 588 |
| **합계** | **5,788** | **27,788** | **11,188** |

(헤드 400 = 포인터 50개×8B, Union-Find 400 = parent·rank 각 50×4B)

- **인접 리스트의 메모리는 간선 수에 비례한다(O(V+E)).**
  무방향 그래프라 간선 하나당 노드가 2개(32B) 생기고, Kruskal은 정렬용 간선 배열 12B를 더 쓰므로 간선당 44B가 든다. 간선이 100개에서 600개로 6배 늘 때 메모리는 5,788B에서 27,788B로 약 4.8배 늘었다. 간선 수와 상관없는 고정 부분(헤드 배열, Union-Find, 결과 배열)이 있어서 6배보다는 적게 늘었다.
- **인접 행렬의 메모리는 간선 수와 무관하게 V²로 고정된다(O(V²)).**
  그래서 희소와 밀집 모두 11,188B이다.
- **희소 그래프**에서는 리스트가 행렬의 약 52%(5,788B ÷ 11,188B)만 쓴다. 행렬의 2,500칸 중 간선이 있는 칸은 200칸(8%)뿐이라 대부분이 낭비된다.
- **밀집 그래프**에서는 행렬이 약 2.5배 적게 쓴다(27,788B ÷ 11,188B). 간선 하나당 리스트는 44B가 들지만 행렬은 양방향 두 칸(8B)이면 되기 때문이다. 이 그래프의 밀도는 약 49%(600/1,225)이다.
- **손익분기점**: Kruskal 총 메모리는 약 1,388 + 44E Byte이고 Prim은 11,188B로 고정이므로, 1,388 + 44E = 11,188에서 E ≈ 223이다. 즉 간선이 약 220개를 넘으면 행렬이 메모리를 덜 쓴다. 정점 50개 기준 밀도로는 약 18%이다.

### 5.2 실행시간: Kruskal vs Prim

| 비교 | 결과 |
|---|---|
| Kruskal: 희소 → 밀집 | 0.0657 → 0.2365 ms (약 3.6배 증가) |
| Prim: 희소 → 밀집 | 0.0879 → 0.0581 ms (약 0.66배, 오히려 감소) |
| 희소 그래프: Kruskal vs Prim | Kruskal이 약 1.3배 빠름 (0.0657 vs 0.0879 ms) |
| 밀집 그래프: Kruskal vs Prim | Prim이 약 4.1배 빠름 (0.2365 vs 0.0581 ms) |

이론상 연산 횟수는 다음과 같다.

| 알고리즘 | 계산식 | 희소 (E=100) | 밀집 (E=600) |
|---|---|---|---|
| Kruskal | E·log₂E (정렬) | 약 660 | 약 5,500 |
| Prim (행렬) | V² + V² (정점 선택 + key 갱신) | 5,000 | 5,000 |

- **Kruskal은 간선 수에 민감하다(O(E log E)).**
  모든 간선을 정렬해야 하므로 간선이 6배 늘자 시간도 약 3.6배 늘었다. 이론 연산 횟수는 약 8배(660 → 5,500) 늘어야 하는데 실제 증가가 이보다 작은 것은 간선 수와 무관한 고정 비용(헤드 배열 순회, Union-Find 초기화, `malloc` 등)이 있기 때문으로 보인다.
- **Prim(행렬 + 선형 탐색)은 간선 수와 거의 무관하다(O(V²)).**
  간선이 몇 개든 정점 선택과 key 갱신에 각각 50×50 = 2,500번씩 비교하므로 연산 횟수가 같다. 이번에는 밀집이 희소보다 오히려 빨랐는데, 이론상 두 값은 같아야 하므로 밀도의 영향이라기보다 수십 μs 단위의 측정 오차(캐시, 타이머, OS 스케줄링, 실행 순서)로 보는 것이 맞다.
- **희소 그래프**에서는 연산 횟수만 보면 Kruskal이 훨씬 적지만(660 vs 5,000) 실제 차이는 1.3배뿐이다. 두 시간이 모두 0.1ms 안팎으로 매우 짧아 고정 비용과 측정 오차가 크게 작용하므로, 이 차이는 의미 있는 차이라고 보기 어렵다.
- **밀집 그래프**에서는 이론 연산 횟수가 비슷한데(5,500 vs 5,000) Prim이 4.1배 빨랐다. 이는 연산 횟수가 아니라 한 번의 연산 비용 차이로 설명된다. Prim은 연속된 배열을 단순 비교만 하지만, Kruskal은 연결 리스트를 따라가며 간선 배열을 만들고(`malloc` 포함), `qsort`가 비교 함수를 약 5,500번 호출한다. 이 부분은 코드 구조에서 추정한 것이고 따로 측정해 확인하지는 않았다. 1회 측정이라 정확한 배수는 믿기 어렵지만, 네 개의 시간 중 가장 큰 차이라 Prim이 더 빠르다는 방향은 신뢰할 수 있다.

### 5.3 그래프 밀도의 영향 정리

| 구분 | 밀도 증가(희소 → 밀집)의 영향 |
|---|---|
| 인접 리스트 메모리 | 크게 증가 (5,788 → 27,788 B, 약 4.8배) |
| 인접 행렬 메모리 | 변화 없음 (11,188 B) |
| Kruskal 시간 | 크게 증가 (약 3.6배) |
| Prim 시간 | 이론상 일정 (이번 측정은 0.66배로 감소했으나 오차 범위로 해석) |
| MST 비용 | 크게 감소 (1399 → 225), 가벼운 간선을 고를 선택지가 늘기 때문 |

- 희소 그래프에서는 리스트 + Kruskal이 메모리 면에서 유리했고, 시간은 두 방식의 차이가 오차 범위 안이라 우열을 가리기 어려웠다.
- 밀집 그래프에서는 행렬 + Prim이 메모리(약 2.5배 적음)와 시간(약 4.1배 빠름) 모두 유리했다.
- 표현 방법과 알고리즘의 조합은 그래프의 밀도에 맞춰 고르는 것이 중요하며, 이번 과제에서는 밀도가 올라갈수록 행렬 + Prim의 상대적 이점이 커졌다.

## 6. 한계와 개선 방향

- 각 Case를 1회만 측정했고 시간이 0.06~0.24ms로 매우 짧아, 타이머 해상도와 캐시·OS 스케줄링의 영향이 크다.
- 코드가 Case 1 → 2 → 3 → 4 순서로 한 번씩만 실행하므로, 가장 먼저 도는 Case 1은 캐시가 준비되지 않은 상태에서, 마지막 Case 4는 이미 준비된 상태에서 재는 순서 효과가 있을 수 있다. Prim에서 밀집이 희소보다 빨랐던 것도 이 영향일 가능성이 있다.
- Kruskal의 시간에는 인접 리스트에서 간선 배열을 만드는 과정(`malloc` 포함)이 들어 있어 Prim보다 불리하다. 이 비용을 정렬·Union-Find 부분과 분리해서 재지 않았기 때문에, 밀집 그래프의 4.1배 차이 중 얼마가 여기서 나왔는지는 확인하지 못했다.
- 개선 방향: 같은 MST 계산을 수천 번 반복해 평균을 구하거나, 정점 수 V를 늘려 실험하면 더 신뢰할 수 있는 시간 비교가 가능하다. 간선 배열 생성 시간을 따로 재는 것도 방법이다.

## 7. 결론

1. 두 알고리즘은 같은 그래프에서 같은 MST 비용을 냈고(희소 1399, 밀집 225), 모든 Case에서 간선 수 49를 만족했다.
2. **메모리**는 표현 방법이 결정한다. 인접 리스트는 간선 수에 비례해 늘고(5,788 → 27,788B), 인접 행렬은 V²로 고정된다(11,188B). 이번 과제에서는 간선이 약 220개를 넘으면 행렬이 더 적게 썼다.
3. **실행시간**은 알고리즘의 특성이 결정한다. Kruskal은 간선 수(E log E)에 좌우되어 밀집 그래프에서 약 3.6배 느려졌고, Prim(행렬)은 정점 수(V²)에 좌우되어 밀도의 영향이 작았다. 그 결과 밀집 그래프에서 Prim이 Kruskal보다 약 4.1배 빨랐다. 다만 희소 그래프의 시간 차이는 오차 범위 안이라 우열을 말하기 어렵다.
4. 따라서 메모리 면에서는 **희소 그래프에 인접 리스트**, **밀집 그래프에 인접 행렬**이 적합하고, 시간 면에서는 밀집 그래프에서 **행렬 + Prim**이 유리하다는 일반적인 결론을 이번 과제가 뒷받침한다.
