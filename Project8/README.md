# 최소 비용 신장 트리(MST) 알고리즘 비교: Kruskal vs Prim

정점 50개의 가중치 무방향 연결 그래프(희소 E=100, 밀집 E=600)에 대해 **인접 리스트 + Kruskal**과 **인접 행렬 + Prim**의 메모리 사용량과 실행시간을 비교한 실험입니다.

## 1. 파일 구성

| 파일 | 설명 |
|---|---|
| `mst_compare.c` | 그래프 생성, Kruskal, Prim, 성능 측정, 결과 출력 (C) |
| `README.md` | 실험 결과와 분석 (이 문서) |

## 2. 빌드 및 실행

```
gcc -O2 mst_compare.c -o mst_compare
./mst_compare            # MST 간선 목록까지 출력
./mst_compare noedges    # 요약만 출력
```
Windows(MSVC)에서는 `cl /O2 mst_compare.c`로 컴파일합니다. 시간 측정은 Windows에서 `QueryPerformanceCounter`, 그 외 환경에서 `clock_gettime(CLOCK_MONOTONIC)`을 사용합니다.

## 3. 구현 요약

- **그래프 생성**: 임의의 신장 트리(49개 간선)를 먼저 만들어 연결성을 보장하고, 자기 루프와 중복 간선 없이 나머지 간선을 추가합니다. 가중치는 1~100의 정수입니다. 생성 후 DFS로 연결 여부를 검사하고, 연결되지 않으면 다시 생성합니다.
- **동일 그래프 사용**: 희소/밀집 그래프를 각각 한 번만 만들고, 같은 간선 목록에서 인접 리스트와 인접 행렬을 모두 만듭니다. 즉 Case 1과 3, Case 2와 4는 정점·간선·가중치가 같고 표현 방법과 알고리즘만 다릅니다.
- **Kruskal (인접 리스트)**: 간선 배열을 만들어 `qsort`로 가중치 순 정렬한 뒤, Union-Find(경로 압축 + union by rank)로 사이클을 판별합니다. 간선이 49개가 되면 종료합니다.
- **Prim (인접 행렬)**: 시작 정점 0에서 `key[]`, `parent[]`, `inMST[]` 배열을 두고, 매 단계마다 선형 탐색으로 최소 key 정점을 선택합니다. 시간 복잡도는 O(V²)입니다.
- **메모리 측정**: `sizeof`로 직접 계산합니다. 그래프 표현, 알고리즘 보조 자료구조, 결과 MST 배열을 포함하고 난수 생성·출력용 메모리는 제외합니다.
- **시간 측정**: 그래프 생성이 끝난 뒤 MST 계산 시작부터 종료까지만 재고, 4개 Case 모두 같은 방법과 단위(ms)를 사용합니다. 각 Case는 1회 측정했습니다.

## 4. 실험 결과

| Case | 그래프 | 표현 | 알고리즘 | MST 간선 수 | MST 비용 | 메모리 (Byte) | 실행시간 (ms) |
|---|---|---|---|---|---|---|---|
| 1 | Sparse (V=50, E=100) | 인접 리스트 | Kruskal | 49 | 1473 | 5,788 | 0.033800 |
| 2 | Dense (V=50, E=600) | 인접 리스트 | Kruskal | 49 | 303 | 27,788 | 0.121200 |
| 3 | Sparse (V=50, E=100) | 인접 행렬 | Prim | 49 | 1473 | 11,188 | 0.023500 |
| 4 | Dense (V=50, E=600) | 인접 행렬 | Prim | 49 | 303 | 11,188 | 0.041800 |

### 결과 검증
- 4개 Case 모두 MST 간선 수가 49(= V−1)입니다.
- 같은 그래프에서 Kruskal과 Prim의 MST 비용이 일치합니다. 희소 그래프는 1473, 밀집 그래프는 303입니다.
- 선택된 간선의 구성과 순서는 다릅니다. Kruskal은 가중치가 작은 간선부터 고르고, Prim은 정점 0에서 확장하는 순서로 고릅니다. 비용이 같으면 정상입니다.
- 밀집 그래프의 MST 비용(303)이 희소 그래프(1473)보다 훨씬 작은 이유는 간선이 6배 많아 가중치가 작은 간선을 고를 기회가 늘기 때문입니다. 밀집 그래프의 MST 간선 가중치는 대부분 1~10 안에 있고, 희소 그래프는 평균 약 30입니다.

## 5. 분석

### 5.1 메모리 사용량: 인접 리스트 vs 인접 행렬

`sizeof(Node)`=16B, `sizeof(Edge)`=12B, 포인터 8B 기준 항목별 계산입니다.

| 항목 | Case 1 | Case 2 | Case 3 / 4 |
|---|---|---|---|
| 그래프 표현 | 3,600 (헤드 400 + 노드 2×100×16) | 19,600 (헤드 400 + 노드 2×600×16) | 10,000 (50×50×4) |
| 알고리즘 보조 구조 | 1,600 (간선 배열 1,200 + Union-Find 400) | 7,600 (간선 배열 7,200 + Union-Find 400) | 600 (key, parent, inMST) |
| 결과 MST 배열 | 588 | 588 | 588 |
| **합계** | **5,788** | **27,788** | **11,188** |

- **인접 리스트의 메모리는 간선 수에 비례합니다(O(V+E)).** 무방향 그래프라 간선 하나당 노드가 2개(32B) 생기고, Kruskal은 정렬용 간선 배열 12B를 추가로 씁니다. 그래서 간선당 약 44B가 듭니다. 간선이 100개에서 600개로 6배 늘자 메모리는 5,788B에서 27,788B로 약 4.8배 늘었습니다. 늘지 않는 고정 부분(헤드 배열, Union-Find, 결과 배열)이 있어서 6배보다 작게 늘었습니다.
- **인접 행렬의 메모리는 간선 수와 무관하게 V²로 고정됩니다(O(V²)).** 그래서 희소와 밀집 모두 11,188B입니다.
- **희소 그래프**에서는 리스트가 약 52% 수준(5,788B vs 11,188B)으로 유리합니다. 행렬의 2,500칸 중 간선이 있는 칸은 200칸(8%)뿐이라 대부분이 낭비됩니다.
- **밀집 그래프**에서는 행렬이 약 2.5배 적게 씁니다(11,188B vs 27,788B). 행렬은 칸 하나가 4B지만 리스트는 간선 하나에 노드 2개와 포인터가 들기 때문입니다. 밀도가 약 49%(600/1,225)인 이 그래프에서는 행렬이 유리합니다.
- **손익분기점**: Kruskal 총 메모리는 약 1,388 + 44E Byte이고 Prim은 11,188B로 고정이라, 간선이 약 220개를 넘으면 행렬이 메모리를 덜 씁니다. 정점 50개 기준 밀도로는 약 18% 정도입니다.

### 5.2 실행시간: Kruskal vs Prim의 특성

| 비교 | 결과 |
|---|---|
| Kruskal: 희소 → 밀집 | 0.0338 → 0.1212 ms (약 3.6배 증가) |
| Prim: 희소 → 밀집 | 0.0235 → 0.0418 ms (약 1.8배 증가) |
| 희소 그래프: Kruskal vs Prim | Prim이 약 1.4배 빠름 |
| 밀집 그래프: Kruskal vs Prim | Prim이 약 2.9배 빠름 |

- **Kruskal은 간선 수에 민감합니다(O(E log E)).** 모든 간선을 꺼내 정렬해야 하므로, 간선이 6배 늘자 시간이 약 3.6배 늘었습니다. 정렬 비용뿐 아니라 인접 리스트를 순회하며 간선 배열을 만드는 비용도 E에 비례합니다. 다만 MST가 완성되면(간선 49개) 반복을 멈추기 때문에, 정렬 이후의 Union-Find 검사는 전체 간선을 다 보지 않을 수 있습니다.
- **Prim(행렬 + 선형 탐색)은 간선 수에 거의 무관합니다(O(V²)).** 정점 선택에 V번 × V칸, 갱신에 V번 × V칸을 쓰므로 간선이 몇 개든 약 2,500~5,000번의 연산이 들어갑니다. 그래서 밀도가 올라도 시간 증가가 Kruskal보다 훨씬 작았습니다.
- **이론 계산량**: 희소 그래프에서 Kruskal은 약 100×log₂100 ≈ 660, 밀집 그래프에서는 약 600×log₂600 ≈ 5,500입니다. Prim은 둘 다 2,500 안팎입니다. 이 값의 비율(희소에서 Kruskal이 더 적고 밀집에서 훨씬 많음)은 밀집 그래프에서 Prim이 유리하다는 실측 결과와 같은 방향입니다.
- **희소 그래프에서도 Prim이 더 빨랐던 점**은 이론(Kruskal이 연산 수가 적음)과 다릅니다. 이는 이론이 틀린 것이 아니라 다음 요인 때문으로 보입니다. 정점이 50개로 작아 연산 수 차이가 미미합니다. Prim은 연속된 배열을 순차적으로 접근해 캐시에 유리하지만, Kruskal은 `malloc`으로 만든 연결 리스트를 따라가고 간선 배열을 `malloc`하며 `qsort` 함수 포인터를 호출하는 상수 비용이 큽니다. 이 때문에 희소 그래프의 시간 순위는 이번 실험만으로 단정하기 어렵습니다.
- **Prim의 밀집 그래프 시간이 희소보다 큰 점**(1.8배)은 이론상 거의 같아야 하는 값입니다. 밀집 그래프에서는 `key` 갱신 조건이 더 자주 참이 되어 쓰기가 늘고, 실제로 더 많은 칸이 0이 아니라 분기 예측 실패도 늘 수 있습니다. 다만 값이 수십 μs라 측정 오차가 크므로, 큰 의미를 두지 않는 편이 안전합니다.

### 5.3 그래프 밀도의 영향 정리

| 구분 | 밀도 증가(희소 → 밀집)의 영향 |
|---|---|
| 인접 리스트 메모리 | 크게 증가 (5,788 → 27,788 B, 약 4.8배) |
| 인접 행렬 메모리 | 변화 없음 (11,188 B) |
| Kruskal 시간 | 크게 증가 (약 3.6배) |
| Prim 시간 | 작게 증가 (약 1.8배, 이론상 거의 일정) |
| MST 비용 | 크게 감소 (1473 → 303), 간선이 많아져 가벼운 간선을 고를 선택지가 늘기 때문 |

- 희소 그래프에서는 리스트 + Kruskal이 메모리 면에서 유리하고, 정점 수가 큰 경우에 시간도 유리해집니다.
- 밀집 그래프에서는 행렬 + Prim이 메모리와 시간 모두 유리했습니다.
- 표현 방법과 알고리즘의 조합은 그래프의 밀도에 맞춰 고르는 것이 중요하며, 이번 실험에서는 밀도가 올라갈수록 행렬 + Prim 쪽의 상대적 이점이 커졌습니다.

## 6. 한계와 개선 방향

- 각 Case를 1회만 측정했고 시간이 0.02~0.12ms로 매우 짧아, 타이머 해상도와 캐시·OS 스케줄링의 영향이 큽니다. 실행할 때마다 값이 달라지고 순위가 바뀔 수도 있습니다.
- Kruskal의 시간에는 인접 리스트에서 간선 배열을 만드는 과정이 포함되어 있어 Prim보다 다소 불리합니다. 간선 배열 생성을 시간에서 뺄지 여부는 구현 관점에 따라 달라질 수 있습니다.
- 개선 방향: 같은 MST 계산을 수천 번 반복해 평균을 구하거나, 정점 수 V를 늘려 실험하면 더 신뢰할 수 있는 시간 비교가 가능합니다. Prim에 힙(우선순위 큐)을 쓰면 인접 리스트와 함께 O(E log V)로 만들어 희소 그래프에서도 비교해 볼 수 있습니다.

## 7. 결론

1. 두 알고리즘은 같은 그래프에서 같은 MST 비용을 냈고(희소 1473, 밀집 303), 모든 Case에서 간선 수 49를 만족했습니다.
2. **메모리**는 표현 방법이 결정합니다. 인접 리스트는 간선 수에 비례해 늘고, 인접 행렬은 V²로 고정됩니다. 이번 실험에서는 간선 약 220개를 넘으면 행렬이 더 적게 썼습니다.
3. **실행시간**은 알고리즘의 복잡도가 결정합니다. Kruskal은 간선 수(E log E)에, Prim(행렬)은 정점 수(V²)에 좌우되어, 밀집 그래프일수록 Prim이 상대적으로 유리했습니다(약 2.9배).
4. 따라서 **희소 그래프에는 인접 리스트(+Kruskal)**, **밀집 그래프에는 인접 행렬(+Prim)**이 적합하다는 일반적인 결론을 이번 실험이 뒷받침합니다. 다만 시간 값은 수십 μs 수준의 1회 측정이라 수치 자체보다 경향을 근거로 해석해야 합니다.
