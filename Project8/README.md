# 최소 비용 신장 트리(MST) 알고리즘 성능 비교 보고서

## 1. 실험 개요

| 항목 | 내용 |
|---|---|
| 그래프 | 가중치 무방향 단순 연결 그래프 (정점 50개, 번호 0~49) |
| 가중치 | 1~100 사이의 임의 양의 정수 |
| Sparse Graph | 정점 50, 간선 100 |
| Dense Graph | 정점 50, 간선 600 |
| 알고리즘 | Kruskal (인접 리스트), Prim (인접 행렬) |
| 구현 언어 | C (`mst_compare.c`) |
| 시간 측정 | MST 계산 구간만 측정 (그래프 생성·출력 제외), 모든 Case를 동일한 방법과 단위(ms)로 1회 측정 |
| 메모리 측정 | `sizeof` 기반 직접 계산 (그래프 표현 + 알고리즘 보조 자료구조 + 결과 MST 배열) |

### 그래프 생성 방법
1. 임의의 신장 트리(49개 간선)를 먼저 만들어 연결성을 보장합니다.
2. 자기 루프와 중복 간선이 생기지 않도록 나머지 간선을 목표 개수까지 추가합니다.
3. 생성 직후 DFS로 연결 여부를 확인하고, 연결되지 않았으면 다시 생성합니다.
4. 희소/밀집 그래프를 각각 한 번만 생성하고, 같은 간선 목록으로 인접 리스트와 인접 행렬을 만듭니다. 따라서 Case 1과 3, Case 2와 4는 정점·간선·가중치가 같습니다.

## 2. 실행 결과

| Case | 그래프 | 표현 | 알고리즘 | MST 간선 수 | MST 비용 | 메모리(Byte) | 실행시간(ms) |
|---|---|---|---|---|---|---|---|
| 1 | Sparse (E=100) | 인접 리스트 | Kruskal | 49 | 1399 | 5,788 | 0.065700 |
| 2 | Dense (E=600) | 인접 리스트 | Kruskal | 49 | 225 | 27,788 | 0.236500 |
| 3 | Sparse (E=100) | 인접 행렬 | Prim | 49 | 1399 | 11,188 | 0.087900 |
| 4 | Dense (E=600) | 인접 행렬 | Prim | 49 | 225 | 11,188 | 0.058100 |

### 결과 검증
- 4개 Case 모두 MST 간선 수가 **49**(= 정점 수 − 1)입니다.
- 희소 그래프: Kruskal 비용 = Prim 비용 = **1399**으로 일치합니다.
- 밀집 그래프: Kruskal 비용 = Prim 비용 = **225**으로 일치합니다.
- 같은 비용이어도 선택된 간선의 구성과 순서는 다를 수 있습니다. 예를 들어 Case 1은 가중치 순으로 간선을 고르고, Case 3은 정점 0에서 확장하는 순서로 고릅니다. 이는 과제에서 허용한 차이입니다.
- 프로그램의 자체 검증 출력(간선 수 49, 비용 일치)도 모두 `OK`입니다.

## 3. 메모리 사용량 분석

### 3.1 항목별 계산

`sizeof(Node)`=16B (to 4 + w 4 + next 포인터 8), `sizeof(Edge)`=12B (u, v, w 각 4B), 포인터는 8B로 계산했습니다.

**Kruskal (인접 리스트)**

| 항목 | Case 1 (E=100) | Case 2 (E=600) | 계산식 |
|---|---|---|---|
| 헤드 포인터 배열 | 400 | 400 | 50 × 8 |
| 인접 리스트 노드 | 3,200 | 19,200 | 2E × 16 (무방향이라 간선당 노드 2개) |
| 간선 배열 | 1,200 | 7,200 | E × 12 |
| Union-Find (parent, rank) | 400 | 400 | 50 × 4 × 2 |
| 결과 MST 배열 | 588 | 588 | 49 × 12 |
| **합계** | **5,788** | **27,788** | |

**Prim (인접 행렬)**

| 항목 | Case 3 (E=100) | Case 4 (E=600) | 계산식 |
|---|---|---|---|
| 인접 행렬 | 10,000 | 10,000 | 50 × 50 × 4 |
| key, parent, inMST 배열 | 600 | 600 | 50 × 4 × 3 |
| 결과 MST 배열 | 588 | 588 | 49 × 12 |
| **합계** | **11,188** | **11,188** | |

### 3.2 해석
- **인접 리스트**는 메모리가 간선 수 E에 비례합니다(O(V+E)). 희소 그래프에서는 5,788B로, 행렬(11,188B)의 약 52% 수준입니다. 밀집 그래프에서는 27,788B로 약 4.8배 늘어나 행렬보다 약 2.5배 커집니다.
- **인접 행렬**은 간선 수와 관계없이 V²로 고정되어(O(V²)) 두 그래프에서 11,188B로 같습니다. 희소 그래프에서는 빈 칸이 많아 낭비가 크지만, 밀집 그래프에서는 공간 효율이 오히려 좋습니다.
- 메모리 손익분기점: Kruskal 총 메모리는 약 1,388 + 44E Byte(노드 32B + 간선 배열 12B를 간선당 사용)이고 Prim은 11,188B로 고정입니다. 따라서 E가 약 220개를 넘으면 Prim 쪽이 메모리를 덜 씁니다. 무방향 그래프의 최대 간선 수는 1,225개이므로 600개는 밀도 약 49%입니다.

## 4. 실행시간 분석

| 비교 | 시간 | 비율 |
|---|---|---|
| Kruskal: Sparse → Dense | 0.0657 → 0.2365 ms | 약 3.6배 증가 |
| Prim: Sparse → Dense | 0.0879 → 0.0581 ms | 약 0.66배 (오히려 감소) |
| Sparse에서 Kruskal vs Prim | 0.0657 vs 0.0879 ms | Kruskal이 약 1.3배 빠름 |
| Dense에서 Kruskal vs Prim | 0.2365 vs 0.0581 ms | Prim이 약 4.1배 빠름 |

### 이론적 복잡도

| 알고리즘 | 복잡도 | V=50, E=100 | V=50, E=600 |
|---|---|---|---|
| Kruskal (정렬 지배) | O(E log E) | 약 100 × 6.6 ≈ 660 | 약 600 × 9.2 ≈ 5,500 |
| Prim (행렬, 선형 탐색) | O(V²) | 2,500 | 2,500 |

### 해석
- **Kruskal**은 간선을 모두 정렬해야 하므로 E가 6배 늘면 시간이 크게 늘고, 측정에서도 약 3.6배 증가했습니다.
- **Prim**은 간선 수와 무관하게 V²번의 연산을 하므로 밀도의 영향이 작아야 합니다. 이번에는 밀집이 희소보다 빨랐는데, 수십 μs 단위의 측정 오차로 보는 것이 맞습니다.
- **밀집 그래프**에서는 Prim이 Kruskal보다 약 4.1배 빨라 차이가 뚜렷합니다. **희소 그래프**의 1.3배 차이는 값이 작아 오차 범위일 수 있습니다.
- **실행 간 변동**: 이전 실행에서는 희소 그래프에서 Prim이 더 빨랐고(0.0235 vs 0.0338ms), 이번에는 Kruskal이 더 빨랐습니다. 반면 "밀집에서 Prim이 크게 빠르다"(2.9배, 4.1배)와 "Kruskal은 밀집에서 약 3.6배 느려진다"는 두 번 모두 같았습니다. 일관된 경향만 근거로 삼아야 합니다.

### 측정의 한계
- 각 Case를 1회만 측정했고 값이 0.06~0.24ms로 매우 작아 타이머 해상도·캐시·OS 스케줄링의 변동이 큽니다.
- 더 신뢰할 만한 비교를 하려면 MST 계산을 수천 번 반복해 평균을 내거나 정점 수를 키우는 것이 좋습니다.
- Kruskal 시간에는 인접 리스트에서 간선 배열을 만드는 과정(`malloc` 포함)이 들어 있어 Prim보다 다소 불리합니다.

## 5. 종합 비교

| 구분 | Kruskal + 인접 리스트 | Prim + 인접 행렬 |
|---|---|---|
| 메모리 | O(V+E): 희소 그래프에서 유리 | O(V²): 밀도와 무관하게 고정, 밀집 그래프에서 유리 |
| 시간 복잡도 | O(E log E): 간선이 많을수록 느려짐 | O(V²): 간선 수와 무관 |
| 희소 그래프 | 메모리 절약 (5,788B < 11,188B) | 시간은 비슷함 (V가 작아 실행마다 우열이 바뀜) |
| 밀집 그래프 | 메모리와 시간 모두 불리 | 메모리와 시간 모두 유리 (시간 2.9~4.1배) |
| 구현 | 정렬 + Union-Find 필요 | 배열만으로 간단 |
| 적합한 상황 | 간선이 적은 희소 그래프, 간선 목록이 이미 있는 경우 | 간선이 많은 밀집 그래프, 정점 수가 작은 경우 |

## 6. 결론
1. 같은 그래프에서 Kruskal과 Prim은 MST 비용이 같았습니다(희소 1399, 밀집 225). 두 구현 모두 올바르게 동작했습니다.
2. **그래프 밀도**는 인접 리스트의 메모리와 Kruskal의 시간에 큰 영향을 줍니다. 반면 인접 행렬의 메모리와 Prim의 시간은 밀도에 거의 영향을 받지 않습니다.
3. **희소 그래프**에는 인접 리스트가 메모리 면에서 유리합니다. 시간은 정점이 50개로 작아 두 방식의 차이가 뚜렷하지 않았습니다.
4. **밀집 그래프**에는 인접 행렬 + Prim이 메모리(11,188B vs 27,788B)와 시간(약 4.1배) 모두 유리했습니다.
5. 시간 측정값이 매우 작고 1회 측정이라, 실행마다 바뀌는 항목은 단정하지 않고 반복해서 일관되게 나온 경향만 결론으로 삼았습니다.
